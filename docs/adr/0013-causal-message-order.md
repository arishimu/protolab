# ADR-0013: 配对消息的因果纵向序

**状态**：已接受（2026-11-02）

## 背景

ADR-0008 规定同一条消息的发送端与接收端不要求共享 y，各端落在各自角色的本地梯子上。现有实现按角色独立解算 y，只保证角色内部顺序与消息端全局唯一，没有跨角色因果约束。两个两方样例中所有配对消息的接收端都高于发送端，自上而下阅读会形成「先接收、后发送」的错误顺序；消息序号与画面顺序也可能不一致。

## 决策

1. 每条配对消息生成一条跨角色因果边：发送端行的底部必须早于接收端行的顶部至少 16 px。
2. 同角色相邻单元自动生成局部顺序边。`solveSpacing` 改为跨角色拓扑放置，Kahn 队列按角色下标、单元下标升序取最小，保证确定性。
3. 单元 y 的下界取「前一单元底 + 档位间距」与「所有前驱底 + 最小间距」的较大值；随后套用禁置带与全局唯一分离。动作区起点由所有角色首行的等式改为下界：首行不得高于统一起点，接收端可以因因果约束下移。
4. 因果约束成环时，丢弃环内因果边，保留其余约束，输出一条 `order-cycle` 冲突，图仍完整渲染，不静默重排。环检测复用配对图的判定。
5. 消息序号按发送端单元 y 升序分配，同 y 按源码 offset 升序；序号一经分配即用于图例、柱标签与 aria。

## 后果

- 修订 ADR-0006 点 5 的动作区起点等式，以及 ADR-0008 点 2 对发送端与接收端相对高度的留白。ADR-0008 的「各端 y 互异」仍然成立。
- 画布高度可能增加；增量由 16 px 最小间距与因果下移共同决定，容器滚动承担超出部分。
- 成环模型不再提供确定的收发顺序，`order-cycle` 冲突必须在画布上可见。
- 消息序号与纵向顺序一致；消息色仍按序号生成，序号稳定则颜色稳定。
