# ADR-0005: 多方的意图配对默认关闭，但可由用户人工声明

**状态**：已接受（2026-09-22）

> **修订（2026-09-22）**：本 ADR 的一对一禁止与重复占用冲突已被 [ADR-0007](0007-broadcast-fanout-manual-pairing.md) 取代。人工配对允许一个发送端接多个接收端，画成一次广播扇出。其余部分继续有效：人工声明仍是设计意图，仅对未配对步骤开放，产出声明式意图边，仅存内存。
>
> **修订（2026-11-02）**：ADR-0008 取消同一条消息共享 y 与同一行约束。人工配对现在声明消息因果边，各端保留角色本地 y，见 [ADR-0008](0008-channel-junction-message-colors.md) 与 [ADR-0013](0013-causal-message-order.md)。下文提到上下对齐、完整消息行或同一行时，均按此修订理解。

ADR-0003 规定生命线多于两条时关闭自动配对、全部标未配对，理由是多方消息路由无法从 `.pv` 静态推断；该 ADR 同时把人工标注每份 `.pv` 的意图流列为被否决的选项。本 ADR 修订其边界：自动配对在多方下仍关闭，ADR-0003 的判据不变；新增运行时人工配对作为可选出路。用户在规范叙事视图里点选两条不同角色的未配对步骤，声明它们是同一条消息，视图标记为人工配对。

理由：多方协议如 `ns-mutual-auth` 在默认局部梯子下无法读出全局消息序。局部梯子的纵轴是各角色本地序，角色间不共享行。该全局序真实存在，源码注释 `(* Message N *)` 即是人写的同一信息，只是无法从 `.pv` 静态推断。把它交还给掌握协议知识的用户，既不静默猜测，也符合 ADR-0003 的约束，并恢复了旗舰样例的可读性。

边界：

1. 人工配对表达的仍是设计意图，不是 Dolev-Yao 可达性，定义与 ADR-0003 相同。安全性只由 ProVerif 的结论回答。
2. 人工配对产出消息因果边，不产出像素坐标。各端落在各自角色的本地梯子，见 ADR-0008；纵坐标由自适应间距模型解算，见 `.scratch/pv-lens-v2/decisions/08-adaptive-spacing.md`。
3. 仅对未配对步骤开放。自动配对好的消息行不可手动移动。
4. 人工配对是一份声明式意图边列表，与自动配对共用 IR。MVP 仅存会话内存，不回写 `.pv`；画布编辑仍属二期。

后果：`CONTEXT.md` 新增人工配对、局部梯子词条，并修订意图配对、未配对步骤；间距解算器需接受外部同序约束输入；本决策不改变 ADR-0003 的自动配对判据。
