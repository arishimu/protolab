# ADR-0005: 多方的意图配对默认关闭，但可由用户人工声明

**状态**：已接受（2026-09-22）

> **修订（2026-09-22）**：本 ADR 的「一对一禁止 / 重复占用冲突」已被 [ADR-0007](0007-broadcast-fanout-manual-pairing.md) 取代——人工配对允许一个发送端接多个接收端，画成「一次广播扇出」。其余部分（人工声明仍是设计意图、仅未配对、声明式意图边、仅存内存）继续有效。

ADR-0003 规定泳道多于两条时自动配对关闭、全部标未配对（多方消息路由无法从 `.pv` 静态推断），并把「人工标注每份 `.pv` 的意图流」列为被否决的选项。本 ADR 修订其边界：**自动**配对在多方下仍关闭（ADR-0003 的判据不变），但改用**运行时人工配对**作为可选出路——用户在规范叙事视图里把两条不同角色的未配对步骤上下对齐，即**声明**它们是同一条消息；视图画成完整消息行并标记「人工」。

理由：多方协议（如 `ns-mutual-auth`）在默认「局部梯子」（纵轴 = 各角色本地序、角色间不共享行）下读不出全局消息序，而这个序是真实存在的（源码注释 `(* Message N *)` 即是人写的同一信息），只是无法从 `.pv` 静态推断。把它交还给掌握协议知识的用户，既不静默猜测（ADR-0003 的底线），又恢复了旗舰样例的可读性。

边界：

1. 人工配对表达的仍是**设计意图**，不是 Dolev-Yao 可达性——与 ADR-0003 同一定义，安全性只由 ProVerif 的结论回答。
2. 人工配对产出**行序约束**（同一条消息 / 同一行），不产出像素坐标；纵坐标由自适应间距模型解算（`.scratch/pv-lens-v2/decisions/08-adaptive-spacing.md`）。
3. 仅对**未配对**步骤开放；自动配对好的消息行不可手动移动。
4. 人工配对是一份**声明式意图边列表**（与自动配对共用 IR），MVP 仅存**会话内存**，不回写 `.pv`（画布编辑仍属二期）。

后果：`CONTEXT.md` 新增「人工配对」「局部梯子」词条并修订「意图配对 / 未配对步骤」；间距解算器需接受「外部同序约束」输入；本决策不改变 ADR-0003 的自动配对判据。
