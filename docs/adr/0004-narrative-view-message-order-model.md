# ADR-0004: 规范叙事视图 v2 的语义模型 = 消息序梯子 + 信道一等元素

**状态**：已接受（2026-09-19）

## 背景

MVP 的规范叙事视图把每条角色渲染成一条泳道，泳道内按**源码顺序**堆叠消息步骤卡片，跨泳道关系靠一条连接两张卡片边缘的折线表示（`pv-lens/packages/web/src/narrative/layout.ts`）。实际使用暴露了成体系的缺陷：

- 两条泳道的卡片游标各自累加，**没有共享的横向坐标**；「对齐」纯属巧合，却被读成「两个进程同时开始」。这是 NS 原版（含 Lowe 攻击）可视化失败的根因。
- **消息不是一等对象**：`out(c, aenc(...))` 与 `in(c, m)` 是两张互不相关的卡片；A 发出的 `{Na,pk(skA)}pkX` 与 B 收到的 `m` 在图上无法被认成同一条消息，信息流割裂。
- 方向、信道、`new`、`event` 全被压成卡片里的文字行，视觉上毫无区分度。

## 决策

重做规范叙事视图的语义模型与视觉语法（v2），锁定如下：

1. **纵轴 = 消息序（梯子）**。一条**消息**是一个一等对象，占一行；发送步骤与接收步骤共享同一 y——对齐因此具有语义（同一条消息），而非巧合。
2. **角色 = 竖直生命线**；**信道 = 一等视觉元素**，以 T2「横线中段信道段」落地：一条消息 = 发送段 + 中段信道段（线型 / 名字）+ 接收段。未配对消息只画一半，端点落在信道轨上。T2 与 T1（总线式）经 prototype 对比后定稿为 T2（`.scratch/pv-lens-narrative-v2/decisions/01-channel-topology.md`）；跨中间生命线的走线用**跨线弧**（在交叉处上拱，避免读成「中继」）。
3. **两层信息模型**：**消息层**（共享、跨角色，承载发送方实际放上信道的 wire term）与**值层**（每角色本地的记号节点与派生边）。接收步骤是两层的连接点：wire term 在此绑定为本地记号。
4. **本地步骤不占箭头**：`new` / `let` / `if` / `get` / `insert` 是生命线上两消息之间的本地节点；`event` 是专门标记。
5. **单符号会话**：一条生命线 = 该角色的一个符号实例；`!` 只表示可重复。多会话展开不在本视图内。
6. **沿用 ADR-0003**：意图配对（设计意图，非可达性）不变；未配对消息挂到信道轨；多方协议不自动配对。

## 被否决的选项

- **保持泳道、只修补**：泳道没有共享坐标，修补无法消除「同时开始」的错觉；且消息仍不是一等对象。
- **信道只作样式**（线型 / 颜色 + 标签）：正是被抱怨的「毫无存在感」；也无法给未配对消息与多方消息一个落点。
- **信道 / 攻击者作为一等参与者**：会把「攻击者能看见」的**可达性**语义带进一个明确表达**设计意图**的视图，与 ADR-0003 的边界冲突；本视图范围也不含反例 / 执行（另立 effort）。
- **值层做词法作用域框**：解析器的进程体是线性展开、变量集只增不减，画作用域框会暗示源码里不存在的控制流；改为**值节点 + 派生边**。
- **跨角色同实体自动统一命名**：需要跨角色等价推断，在攻击场景下会推出错误结论。

## 后果

- `pv-lens/packages/web/src/narrative/layout.ts` 的泳道布局与卡片模型将被 v2 取代；`pv-lens/packages/core` 需要产出「消息对象 / 本地步骤 / 值绑定与引用」的数据（最小形状见 `.scratch/pv-lens-narrative-v2/decisions/07-core-value-model.md`）。
- `CONTEXT.md` 的词条随之更新：**规范叙事视图**不再定义为「泳道呈现」；新增**消息**（一等对象）、**值层**、**信道轨**、**本地步骤**、**事件标记**。
- 端到端验证（验证结论面板）与事件对应性交互（点两支旗查表）沿用并扩展。
- 反例 / 执行视图、多会话展开、攻击图导出为 out of scope，另立 effort。
