# ADR-0012: 身份色按身份标识稳定生成并保持单射

**状态**：已接受（2026-11-02）

## 背景

值身份色与消息身份色此前各使用 8 个 token，按插入序取模。四个基准样例的绑定数已超过 8 个，跨角色同名绑定与不同名绑定都会出现同色。颜色因此无法表达「同色即同值」，与 U4.3 冲突；T1 已将该问题登记为未解决。

## 决策

1. 值身份色与消息身份色按身份标识稳定生成。值色使用高明度、低饱和色域，保证深色文字可读；消息色使用中明度、高饱和色域，保证细线与柱可辨。
2. 颜色分配以身份标识的 FNV-1a 哈希为首选槽位。同一画布内按身份标识排序后逐个放置；若槽位已占用，按固定步长探测下一个槽位。输出只依赖身份集合，不依赖输入顺序。
3. 同一画布内不同身份不同色，同色当且仅当同身份。颜色是识别通道，值序号与消息序号是权威标识。
4. 消息色前 8 个 token 沿用既有视觉基准；第 9 条起继续生成并避开前 8 个 token。值色不沿用固定 8 色，直接由生成器给出。
5. 箭头 marker 按消息动态生成，标识含消息 id，填充该消息色；不再按 8 色下标生成 marker。

## 后果

- 解决 T1 与 T2 的色板部分。图例中的「八色轮转」表述失效，改为「颜色由绑定身份稳定生成，序号为权威标识」。
- `ticket09` 中「超八色必须出现同色」的断言编码了旧缺陷，改为「超八色仍无同色不同身份」。
- 身份数量超过色域容量时仍会回退；该情形由序号承担最终区分，颜色单射只在容量内成立。
- 值色生成器与消息色生成器分离，避免值层与消息层颜色语义互相占用。
