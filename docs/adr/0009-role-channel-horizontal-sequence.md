# ADR-0009: 生命线与信道的水平序列 = 加权 min-max 割边的线性排列

**状态**：已接受（2026-09-23）

规范叙事视图的水平轴不是「角色分到信道左右两侧」，而是一个**生命线与信道的交错序列**（`σ`）；左右二分只是单信道时的特例。序列用角色–信道**多重边图**上的**加权 min-max 割边**（cutwidth）目标求解，边集由**消息步骤**给出，因此**不依赖配对结果**。

## 背景

ADR-0007 点 5 要求「角色按通联图二分割、最忙角色贴总线」，但把通用算法留成空白，原型是手工按 `ns-mutual-auth` 一份样例分的。ticket 11 追问通用口径时，逐一否定了三个原始表述：

1. **「通联图二分割（割边最少）」是笔误**——图上 min-cut 的最优解是把所有角色放同一侧，与「最小化同侧消息数」方向相反。
2. **「最小化同侧消息数」不可算**：它需要「设计上发了哪几条消息」，而多方协议自动配对关闭（ADR-0003），人工配对前图为空、且随配对变化；类型门候选图实测把最中心的角色判成孤立点。
3. **多信道击穿单侧二分**：多信道下一个角色可以「夹在信道 1 与信道 2 之间」，全局 left/right 不再有意义。

用户的重新表述给出了可解的模型：把角色与信道一起排成序列，最小化相邻缝隙上的**最大割边数**。

## 决策

1. **模型 = 水平序列**：水平轴是 `V1`（角色，`narrativeRoleOrder`）∪ `V2`（信道）的一个排列 `σ`。单信道时退化为「若干角色 │ 总线 │ 其余角色」。
2. **输入图是角色–信道多重边图**，**pairing-free**：`E` = 每个消息步骤（`out` / `in`）一条边，连「角色 ↔ 该步骤点名的信道」，权 `w_e` = 重边次数。不依赖自动 / 人工配对（ADR-0003 未配对步骤落信道轨；ADR-0008 信道是每个步骤的结点）。
3. **目标 = 加权 min-max 割边（cutwidth）**：
   `σ* = argmin_σ max_{k ∈ {0..n-2}} cut(k)`，`cut(k) = Σ_{(u,v)∈E} w_e·[σ(u) ≤ k < σ(v)]`。
4. **确定性三级 tie-break**：min-max → 同分取降序 cut 曲线字典序最小（majorization-minimal，即最均匀） → 仍同分按源码序（角色 `narrativeRoleOrder`、信道源码首次出现序）取字典序最小 `σ`。
5. **退化情形不做特例**：0 项不画；无缝隙 `max ∅ = 0`；`E = ∅` 由规则 4 兜底；无步骤的孤立角色由规则 4 定位置。
6. **删除同侧 jog**：ADR-0008 已定「各端 y 必须不同」，「同侧收发段共线」不再发生；`SAME_SIDE_JOG`（ADR-0007 点 6）与 ticket 09 的 `BASE_IDX` 起手错位一并删除，「任两消息端的 y 不同」改立为纵向间距解算器（ADR-0006）的硬约束。
7. **MVP 无 UI 覆盖**：算法是纯函数 `σ(G)`。求解器接受「外部顺序约束」列表（会话内存、不回写 `.pv`）作为 seam；未来拖拽 = 加约束重解（与 ADR-0005 人工配对同族）。

## 被否决的选项

- **min-sum（MLA，等价于「总走线长度 / 跨线弧最少」）**：与 min-max **不等价**（加权见证：`V1={r0,r1,r2}`、`V2={c0,c1,c2,c3}`、边权 `r0–c0 ×1, r0–c2 ×1, r0–c3 ×2, r1–c0 ×1, r2–c2 ×2`——min-max = 2 时 sum ≥ 11；min-sum = 8 时 max = 3）。本 ADR 选 min-max；「均匀」由 tie-break 规则承担，不退回 min-sum。
- **简单邻接（无权）图**：同一角色对同一信道的多个步骤是物理上多条走线段，忽略重数会丢掉真实负载；且无权小规模图上两种目标的经验上总相交，无法反映我们实例的性质。
- **自动分侧 = 通联图二分割 / 类型门候选图**：输入不可靠（见背景 2），且多信道不成立。
- **完全交用户决定（不做算法）**：水平轴仍需要一个默认；纯朴素默认（源码序）会在旗舰样例上把最重的边放成同侧。

## 后果

- **取代 ADR-0007 点 5、点 6**（点 5「通联图二分割」→ 本 ADR；点 6「同侧 jog」→ 删除）；ADR-0007 其余部分（画布点选声明、一个 `out` 接多个 `in`、广播分组不进 IR）继续有效。
- 序列只决定 `x`（角色与信道位置）；纵向间距 / 局部梯子 / 值层不受影响，序列是布局的**输入**，不触发 y 重解。
- 新增「y 全局唯一」为 ADR-0006 解算器的硬约束（取代 ticket 09 的 `BASE_IDX`）。
- ticket 14（多信道视觉）以本 ADR 的序列为输入，继续管信道视觉编码（总线管、分道、配色、图例、跨线弧画法）。
- 规模 `n ≤ ~10`，全排列或子集 DP `O(n·2^n)` 精确解。
- **tie-break 2 的已知后果**：单信道时，每一侧由总线向外**权重递减**——最忙的角色贴总线、最轻的在最外。这是「降序 cut 曲线字典序最小」的自然结果（一侧的缝隙割边由总线向外是 `T, T−a, T−a−b, …`；降序曲线里除两个「侧总和」外就是这些外层前缀和，压小它们 ⇒ 重者靠内），因此**不再需要**一条显式的「最忙角色贴总线」规则（ADR-0007 点 5 的旧措辞）；实现时**不要**把它加成独立规则，否则会与 min-max 目标打架。已由 ticket 15 原型在 `ns-mutual-auth`（`S·I·c·R·K`，左内侧 I(6)/外侧 S(2)，右内侧 R(7)/外侧 K(1)）上验证。
- `CONTEXT.md` 新增「水平序列」；ticket 11 定稿；原型另开子票（`.scratch/pv-lens-narrative-v2/prototype/09-role-side-assignment.html`，ticket 15 已验证）。
