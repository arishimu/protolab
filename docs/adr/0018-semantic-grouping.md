# ADR-0018: 语义分组（密码操作组与交换段）

**状态**：已接受（2026-11-05）— 阶段 0 验收通过，用户复核后接受；后续实施变更须另立修订或新 ADR。
**适用分支**：`dev`；基线提交 `98dfeec`。

## 背景

规范叙事视图把密码操作展开为逐个方法盒、把消息展开为逐条消息行。读者必须先掌握算子语法，才能看出「这里做了一次签名」或「这一段是一次握手往返」。这是第一道知识门槛。现有**密度折叠**只解决空间不足：它把算子簇折成一格，触发条件是纵向拥挤，语义单位仍是「本地节点」。

另有一道独立门槛在判定侧：验证结论按查询逐条给出，查询与画布、源码之间没有稳定锚定。分组只能降低第一道门槛，不能替代判定解释与归因。

本 ADR 只裁定**语义分组**：值层的密码操作组与消息层的交换段。它把「阅读层次」从「空间压缩」中拆出来，作为可独立开关的派生视图。

## 决策

### 1. 分组是派生视图

1. `.pv` 文本仍是唯一真源（沿用 ADR-0001）。分组 IR 由 `ParseResult` 经纯函数派生，不写入 `ParseResult`，不回写 `.pv`。
2. 分组不改变 ProVerif 的输入文本、查询集合与验证结论（不变量 I2）。
3. 分组不改变水平序列、角色顺序与消息因果序（I3）。展开全部时，布局须与改动前基线的结构一致（I10）。
4. 分组 IR 必须可回溯到 `ParseResult` 的词项、端点与源码 span，不得引入第二套协议模型。

### 2. 两类语义分组

| 分组 | 层次 | 定义 | V1 边界 |
|---|---|---|---|
| 密码操作组 | 值层 | 由一次密码操作出现所覆盖的方法盒与值方块组成的语义单元；按词项结构嵌套，不跨操作合并 | 低置信不自动折叠；元组与变量引用不单独成组 |
| 交换段 | 消息层 | 规范叙事视图中一段因果凸的消息集合；段内消息整体折叠为段框 | 仅两方、单层、单信道、完整消息；不自动建议 |

### 3. 不变量

| 编号 | 不变量 |
|---|---|
| I1 | `.pv` 文本是唯一真源；分组结果、段框与展开状态均为派生数据。 |
| I2 | 分组不改变 ProVerif 的输入文本、查询集合与验证结论。 |
| I3 | 分组不改变水平序列、角色顺序与消息因果序。 |
| I4 | 隐藏项须计数并可展开；不得静默隐藏。 |
| I5 | 跨组引用与跨段边须可见；无法保留时不得折叠。 |
| I6 | 值身份颜色在折叠前后一致；被后续引用的输出保留幽灵值块。 |
| I7 | 分组标签只表示操作种类或阅读单位，不构成保密性、认证或可达性结论。 |
| I8 | 用户声明仅存会话内存，切换协议或刷新即清除，不回写 `.pv`。 |
| I9 | 交换段每次只包含完整消息；一条消息的任一端点在段外时，该范围非法。 |
| I10 | 展开全部时，布局须与改动前的基线在结构上一致；不得因分组引入新的冲突、重叠或裁切。 |

### 4. 操作种类与来源

1. 操作种类取值为：签名、对称加密、对称解密、非对称加密、非对称解密、哈希、密钥派生、未识别。
2. 分组来源取值为：方程匹配、名称启发、用户声明、未识别。来源与置信度必须在审计面板可见。
3. 识别优先级：方程匹配 > 名称启发 > 用户声明覆盖 > 未识别。用户声明可改变种类与来源，但不改变 `.pv`，且仅存会话内存。
4. 低置信与未识别操作**不自动折叠**，保留原始函数名；不得把「未识别」显示为错误。
5. 操作种类标签只是阅读单位，不表示认证、保密或可达性成立（I7）。

### 5. 视觉记法与密度折叠的区分

| 维度 | 语义折叠（本 ADR） | 密度折叠（ADR-0006、决策票 04） |
|---|---|---|
| 触发 | 当前阅读层次不需要该细节 | 空间不足或默认密度设置 |
| 单位 | 密码操作组、交换段 | 本地算子簇、分支团、角色细节 |
| 边框 | 双线边框 + 分组括号字形 | 单线虚线 |
| 方向 | 构造横置、解构竖置（形状区分） | 无方向语义 |
| 计数 | 操作种类、方向、关键参数、密钥身份、隐藏计数 | 算子名与数量 |
| 灰度/打印 | 边框线型与角标可辨，不依赖颜色 | 虚线可辨 |

语义折叠与密度折叠可叠加。两者必须有不同记法与图例条目；不得共用同一边框或同一「折叠」字样而不加限定。

### 6. 模块边界

| 模块 | 职责 |
|---|---|
| `core/parser` | 保留 `reduc` 方程左右两侧与 `fun` 属性、span |
| `core/grouping` | 操作注册表、分类器、分组 IR、段凸性校验；纯 TypeScript，不依赖 DOM |
| `web/narrative/structured-layout` | 分组高度、展开状态与段框的确定性布局 |
| `web/narrative` | 渲染折叠态与展开态、交互、样式；不重新解析 `.pv` |

### 7. 非目标

- 交换段的自动识别、嵌套段、多方段、跨信道段。
- 把广播扇出或合流拆到两个交换段。
- 画布编辑、拖拽生命线、分组结果回写 `.pv`。
- 反例的几何攻击路径、`-graph`/`-html` 攻击图导出。
- 以分组标签推断协议安全结论。

## 后果

- 读者可在值层按操作、在消息层按交换段切换阅读层次；隐藏项均有计数与展开入口。
- 布局器新增两类刚性单元：密码操作组与段框。展开态必须回归到基线结构，测试须同时覆盖折叠与展开。
- 分类依赖 `reduc` 方程结构化；阶段 1 需要扩展解析模型，但不得把视图概念带入 `ParseResult`。
- 审计面板成为分类可核对与可覆盖的唯一入口；用户覆盖仅存会话内存。
- 交换段受 V1 限制：两方、单层、单信道、完整消息；非法范围必须就地拒绝并说明原因。
- 文档需同步：`CONTEXT.md` 新术语、`requirements.md` 的 U10 与相关条目、`docs/summary.md` 阶段记录。
