# ADR-0002: ProVerif 只经 CLI 适配器调用，MVP 不打包分发

后端不内嵌、不链接 ProVerif：只通过一个 CLI 适配器 `spawn` 可执行文件来调用，proverif 可执行文件的路径可注入，并支持超时与取消。MVP 假设运行机器已自行安装 ProVerif（本机 `~/.opam/default/bin/proverif`），**不**随应用打包分发；把「自带二进制 / 容器化」留作后续独立决策，接缝已在适配器里预留。

理由：ProVerif 是独立 OCaml 工具、无稳定库级 API，内嵌调用不现实；它作为静态二进制分发的跨平台成本与研究许可条款尚未解决，不值得在 MVP 期承担。收窄接口后，将来换 bundle、换容器、换验证后端都只改适配器一处。

被否决的选项：内嵌调用（无稳定 API）；MVP 即打包分发（跨平台二进制 + 许可成本，价值未验证）。

后果：安装文档必须写明「需要本机 ProVerif 2.x」及路径注入方式；解析与调用失败要区分「找不到可执行文件」与「验证报错」两类错误呈现给用户。
