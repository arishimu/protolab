# ADR-0010: 多信道的信道身份用几何，颜色只留给消息与值

**状态**：已接受（2026-09-23）；2026-11-04 随第二轮 R09/R17 修订序号与线型的生成口径。

## 背景

01–09 的信道规则只在**一条**信道下验证过（四个内置样例的信道全是 `c`）。ADR-0008 已把「配对箭头用信道色」改成**消息身份色**，但留下一个未收口的冲突：颜色有三套语义在抢——**消息身份色**（一色一消息，ADR-0008）、值层的**值身份色**（一色一值，ticket 02）、以及**信道色**。ticket 14 用 `.scratch/pv-lens-v2/prototype/10-multi-channel-visuals.html` 的三个结构性不同的变体（A 中性几何 / B 低饱和色带 / C 单一分组总线 + 无彩）在 2–3 条信道下对比后定稿。

## 决策

1. **信道不占颜色**。信道身份用**几何**表达：在 ADR-0009 水平序列里的**位置** + **序号字形**（① ② ③）+ **总线方块边框的线型**（实线 / 长虚 / 点线）。多信道 = **并列多条中性总线方块**，不是同一总线分道。
2. **颜色只留给两层**：**消息身份色**（一条消息一种颜色，画在总线内的消息柱、消息段与箭头）与值层的**值身份色**（一色一值，画在值方块上）。两者靠画法载体区分（线 / 柱 vs 块）。
3. **保留**：未配对端点为**橙色开放圆点**，落在其信道的总线壁上（橙色不作为信道色）；单一信道时退化为「一条中性总线 + 消息色 + 值色」，观感与现状一致。**修订（2026-09-24）**：跨中间生命线与中间信道的走线不再用**跨线弧**（ADR-0004 点 2 同步修订），一律直线——用户以 `.scratch/pv-lens-v2/prototype/05-density-folding.html` 为视觉基准定稿。
4. **同信道硬约束不变**：配对仍按信道词项相等匹配（ADR-0003），与信道的视觉编码无关；人工配对的「同信道」约束照旧。
5. **修订（2026-11-04，R09/R17）**：序号字形与总线边框线型统一按水平序列中**从左到右的位置**生成（布局输出 `channelOrder`，`channelLineStyleOf` 纯函数），不再混用声明的收集顺序——序号、tooltip、图例与线型四者从同一位置派生；超过五个信道时序号退化为 `(n)` 形式并在图例说明。总线边框线宽提至 2px，三线型墨迹密度分层（实线、约 58%、约 25%），灰度与打印条件下按密度即可指认信道。

## 被否决的选项

- **变体 B（信道 = 低饱和色带）**：信道占掉大面积颜色，消息身份色必须退成编号徽标，扫读「哪些端点是同一条消息」的线索被削弱。
- **变体 C（单一分组总线 + 子道）**：把信道收拢到一侧会退化成 **T1 式绕行**（同一侧消息绕到总线再折回、出现平行双线），并丢掉 ADR-0009 的「角色夹在两条信道之间」——T2 当初正是为此淘汰 T1。

## 后果

- 收口 ADR-0008 的遗留：「消息身份色 vs 值身份色 vs 信道色」冲突以**信道退出颜色**解决；`CONTEXT.md` 的**消息身份色**词条同步更新，`信道色` 列为避免用词。
- ticket 14 定稿 `.scratch/pv-lens-v2/prototype/10-multi-channel-visuals.html`（变体 A）与 fixture `pv-lens/packages/core/fixtures/pv/multi-channel.pv`。
- 消息色板与值色板的具体取值、同屏可区分性，属**视觉语法细节层**，交 `/to-spec`（不另立票）。
