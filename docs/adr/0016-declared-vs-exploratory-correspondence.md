# ADR-0016: 对应性矩阵区分声明目标与探索性有序对

**状态**：已接受（2026-11-02，2026-11-03 修订）

## 背景

U5.4 要求工具为同参数集合下的全部有序事件对生成 `inj-event(e_i) ==> inj-event(e_j)` 查询。现有实现严格生成 n² 条查询，但不读取源码中用户声明的查询。矩阵中所有 `false` 单元复用「该查询不成立，攻击路径见下方反例 trace」的说明，使工具枚举出的、并非协议安全目标的组合被表述为攻击路径。握手修正版因此出现 9 个红色 ✗，与首页「全绿」标签冲突。

## 决策

1. `CorrespondenceQuery` 增加可选字段 `declared`、`declaredText` 与 `declaredInjective`。`createCorrespondencePlan` 从 `ParseResult.queries` 提取事件名有序对，与生成的 from/to 名称及方向匹配；匹配成功者为源码声明的安全目标。
2. 同名事件在多个角色出现时，先按参数类型匹配，再按源码顺序匹配；仍无法唯一确定时标记为声明匹配不确定，不默认归为安全目标。
3. 用户声明为非单射 `event` 时，矩阵声明格按原查询语义运行，生成的查询使用 `event`，不使用 `inj-event`。只有探索性有序对使用 `inj-event` 探针；另行展示单射强化探针时，必须注明其判定不等价于原查询，且不得单独表述为声明目标被证伪。
4. 矩阵单元格与详情区分源码声明的安全目标与探索性有序对。只有声明目标的 `false` 使用「安全目标被证伪，攻击路径见反例 trace」措辞；探索对的 `false` 使用「该有序对不成立，由工具枚举，不构成协议攻击」。
5. 默认仍生成全部 n² 条查询，保持 U5.4 的批量范围。增加「仅显示源码声明的安全目标」开关，开关只过滤视图，不改变验证文本与查询集合。
6. 首页样例标签「全绿」改为「查询全部成立」，说明中区分声明目标与探索对。
7. 2026-11-03 修订：第 3 条由声明目标仍以 `inj-event` 探针运行改为声明目标按原查询语义运行。原因是握手修正版的非单射声明查询在验证面板证明成立、在矩阵中被单射探针证伪，界面出现相互矛盾的结论；探针判定不能替代原查询判定。矩阵标题与详情同步说明这一区分。

## 后果

- 矩阵的 ✗ 不再一律解释为攻击；声明目标的判定与其在原查询中的判定一致。
- 探索性有序对的 `inj-event` 探针仍保留；声明目标与非单射探针的结论不再共用同一格。
- `ticket08` 的标题断言改为分别报告事件数、有序对数与声明目标数。
- 声明匹配依赖事件名与参数类型；同名多实例无法唯一匹配时呈现为不确定，不做推断。
- 批量查询数量不变；声明目标使用原查询语义，探索对仍使用 `inj-event` 探针。
