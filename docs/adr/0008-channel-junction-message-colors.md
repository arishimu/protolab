# ADR-0008: 信道 = 扇出 / 合流的唯一结点；一色一消息 + 同色柱

**状态**：已接受（2026-09-22）

## 背景

ADR-0007 把人工配对的一对多画成「**广播行**」：同一 y、一条发送段 + N 条接收段，接收端被多条消息收到时用「**收到 ×N 梁**」连起多行。它解决了「`processS` 只有一对 in/out 却要承担 Message 1/2/4/5」的建模问题，但把两件纵向编排的事交回了 map。

ticket 10 用原型在**完整值层**下验证时发现：共享行 y 会把不同角色的本地内容拉到同一 y（R 的 `r_in5` 被拉到 `r_out4` 之上 → 「广播 · 跨序」），并可能被读成「同一个值 / 同一个时间点」。用户据此定稿新模型：**信道是扇出 / 合流的唯一结点，各端 y 必须不同，颜色编码消息身份，整团扇出 / 合流是一个刚性间距单元**。原型 `.scratch/pv-lens-narrative-v2/prototype/07-broadcast-row-alignment.html`（v3）为准。

## 决策

1. **信道 = 扇出 / 合流的唯一结点**。一发多收 = 一条消息的发送端唯一一条进信道、信道「一分为多」出到 N 个接收端；多发一收 = N 条不同消息进信道、信道「多合为一」出到同一个接收端。两者是**同一种画法**（一根同色柱 + 抽头），区别只在抽头落在哪一侧。
2. **各端 y 必须不同**。每个消息端直接落在**角色本地梯子 y**，取消广播行的「共享行 y」。同一条消息的发送端与接收端不再要求同 y。
3. **一色一消息 + 信道管内同色柱**。颜色编码**消息身份**（一条消息一种颜色，与值层「一色一值」并列）；信道管加宽为多道，每条消息一根同色柱，**柱的跨度 = 该消息各端的 y 区间**，柱道按 y 区间是否重叠分配。合流处进入同一步的抽头用**多色并排**表示多条消息。1-1 消息也各一色、各有自己的柱。
4. **整团扇出 / 合流 = 一个刚性间距单元**。结构内部端点的相对 y 由各角色本地梯子给出、固定不变；整团移动、团内不插间隙、不参与等距压缩。
5. **删除「广播 · 跨序」**（无共享行即无跨序）、**删除「收到 ×N 梁」**（由合流的同色柱表达）。

## 被否决的选项

- **共享行 y（ADR-0007 原案）**：把不同角色的本地内容拉到同一 y，制造跨序，且易读成「同一处理时刻」。
- **「收到 ×N」竖梁**：与信道的「多合为一」重复；梁越多越向外堆，正是本票要解决的问题。
- **进信道前先合流为一条**（用户曾提出的另一读法）：把合流点从信道移走，反而分裂了「信道是唯一结点」；采用「N 条进 — 1 条出」。
- **用固定的信道色画所有配对箭头（ADR-0004 原口径）**：在多消息 / 扇出 / 合流下无法区分是哪一条消息；改为消息身份色。

## 后果

- **部分取代 ADR-0007**：点 2（同一 y）、点 3（收到 ×N 梁）、点 4（广播 · 跨序）失效；其余（画布点选声明、一个 `out` 接多个 `in`、广播分组是视图层派生不进 IR、角色按通联图二分割、收发同侧 jog）继续有效。
- **修订 ADR-0006**：其「同一条消息 = 同 y 硬约束」与「跨角色耦合（发送方单元边界 = 消息行 + 接收方簇底）」在**扇出 / 合流**处被「整团刚性单元」取代；1-1 消息仍可沿用原耦合口径。
- `CONTEXT.md` 新增词条**广播扇出 / 合流 / 消息柱 / 消息身份色**，修订**消息 / 跨角色耦合**。
- ticket 10 定稿：`.scratch/pv-lens-narrative-v2/prototype/07-broadcast-row-alignment.html`（v3）。
- **遗留**：消息身份色 vs 值身份色（「一色一值」）vs 信道色的语义冲突，交 ticket 14（多信道视觉）收口；**已由 [ADR-0010](0010-multi-channel-geometric-identity.md) 收口：信道退出颜色**（信道身份用几何），颜色只留给消息身份色与值身份色。
