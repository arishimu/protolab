# ADR-0007: 人工配对的一对多是一次广播扇出，不是多条相同连线

**状态**：已接受（2026-09-22）

> **修订（2026-09-22）**：点 2 同一 y、点 3 收到 ×N 梁、点 4 广播 · 跨序已被 [ADR-0008](0008-channel-junction-message-colors.md) 取代。信道是扇出与合流的唯一结点，各端 y 必须不同，一色一消息，信道管内同色柱，整团扇出或合流作为一个刚性单元。
>
> **修订（2026-09-23）**：点 5 角色按通联图二分割与点 6 收发同侧 jog 已被 [ADR-0009](0009-role-channel-horizontal-sequence.md) 取代。水平轴改为生命线与信道的水平序列，按加权 min-max 割边求解，同侧 jog 删除。其余部分继续有效：点 1 画布点选声明，广播分组是视图层派生、不进入 IR。

ADR-0005 给人工配对定为一对一：一对多与多对一禁止，重复占用高亮冲突。旗舰样例 `ns-mutual-auth` 的 `processS` 只有一对 `in(c,(a,b))` / `out(c,sign((sb,b),skS))`，却承担 Message 1/2（I↔S）与 Message 4/5（R↔S）。一对一放不下，7 步叙事无法做出。本 ADR 修订该边界：一个发送端可以接任意多个接收端，画成一条消息进入信道、信道扇出到各接收端。

## 决策

1. 交互：画布上点选一个端点，再点另一个端点即完成声明；重复点同一个源即做一对多，如 `s1, s2, s1, s3 ⇒ s1 广播给 s2 与 s3`。无拖拽，无局部序重排，复用无上限。
2. 一行 = 一次广播：按发送端归组配对，一个 `out` 与其全部 `in` 合成一行；一条发送段进信道，N 条接收段出信道，同一 y，角标为 `广播 ×N`。不再出现多条相同的发送连线。
3. 接收端多行：一个接收端被多条不同消息收到时，如 `s_in1` 收 Message 1 与 4，它在多行各出现一次，用竖向的收到 ×N 梁连起来。发送端永不占多行。
4. 广播 · 跨序是合法状态：广播行的时间位置与某角色本地序冲突时，布局自动拆解该矛盾边，把广播行移到自洽位置，标 `广播 · 跨序` 并用琥珀色，不计为冲突。真实环仍标红为冲突。
5. 角色相对信道的位置按通联图二分割：消息数最多的角色单独一侧，其余在另一侧，最忙者贴总线。数组顺序仍是源码角色序 `narrativeRoleOrder`。
6. 收发同侧去重叠：接收段在总线边竖向分叉，逐级下移固定小量，原型为 `SAME_SIDE_JOG = 11px`，避免与发送段共线。

## 边界

1. 人工配对表达的仍是设计意图，不是 Dolev-Yao 可达性，定义同 ADR-0003。
2. 只产出顺序约束，即同一行与广播关系；像素 y 由自适应间距模型解算（ADR-0006）。本 ADR 放宽 ADR-0006 与 ticket 05 的同一条消息 = 同 y 约束，广播行允许一条消息跨越多个角色时间点。
3. 仅对未配对步骤开放；自动配对好的消息行不可手动移动。
4. 广播分组是视图层的派生，不进入 `MessagePairing` IR。IR 仍是 `{ outEnd, inEnd, origin }`，一个 `outEnd` 可出现在多条里。
5. 仅存会话内存，不回写 `.pv`；画布编辑归二期。
