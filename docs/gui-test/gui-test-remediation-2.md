## 1 结论摘要

主链路可完成：解析、规范叙事视图、源码双向定位、ProVerif 验证、反例 trace、人工配对、多信道与对应性矩阵均可运行。上一轮整改的 P0–P3 大部分仍然有效，未发现核心阅读链路的回退。

本轮共记录 20 项。按严重程度分为三组。

| 组别 | 项数 | 内容 |
|---|---:|---|
| P0 判定归属与状态一致性 | 3 | 声明目标的单射探针、成立查询的 `goal reachable` 文案、撤销后的配对状态 |
| P1 长模型可读性与交互 | 9 | 画布视口、事件标签、人工配对命中、图例膨胀、窄屏布局、信道序号、错误文案、降级语法、trace 与 stdout |
| P2 排版、文案与可达性 | 8 | 矩阵尺寸、验证卡片密度、分支字号、源码分栏、信道线型、正文行宽、首页入口、键盘可达性 |

问题的共同来源可归纳为七处。

1. 声明目标与单射探针共用同一判定字段和同一套措辞，导致矩阵与验证面板给出相互矛盾的结论。
2. `goal reachable` 同时用于证明见证和攻击路径，界面没有按判定方向分流。
3. 画布视口与缩放策略以宽度适配为目标，没有最小可读字号与整页适配。
4. 标签放置与断行以字符预算为准，没有画布边界与语义边界。
5. 人工配对的命中目标是端点线，可见的词项芯片不参与交互。
6. 图例把无界的值身份清单放入单个网格单元，行高由最长项决定。
7. 面向用户的文案与内部枚举共用同一字段。

## 2 修复原则与约束

### 2.1 原则

1. **判定归属优先于批量完整性。** 源码声明的查询按其原语义判定；单射探针只作为探索性结果，不得替代声明目标的结论。
2. **证明见证与攻击路径分离。** `is true` 的 `goal reachable` 是证明中的对应事实；`is false` 的 `goal reachable` 才构成攻击路径摘要。
3. **原文保真。** 标签换行、截断与降级呈现不得改变源码字符，不得在标识符内部断行，不得插入原文不存在的空格。
4. **最小可读字号。** 缩放不得以牺牲可读性为代价；长模型提供适合页面或全屏能力，窄屏保留 100% 与横向滚动。
5. **单一真源。** 信道序号、图例、矩阵、验证结论与 tooltip 从同一数据源派生，不各自计算。
6. **面向用户的文案不出现内部枚举。** 机器类别、接口路径、ADR 编号与实现细节放入可折叠的技术细节，不进入主提示。
7. **测试基线只增不减。** 编码旧缺陷的断言改写时，用例总数不得减少；新增用例按 `ticketNN-<area>.test.ts` 命名。

### 2.2 约束

- 不修改 `.pv` 文本，不引入画布编辑，不将人工配对回写源码。
- 人工配对仍只存会话内存，切换协议或刷新即清除。
- 规范叙事视图仍只表达设计意图，不表达攻击者可达性。
- 对应性矩阵仍生成全部 n² 有序对；声明目标与探索性有序对的分层保持不变。
- 所有改动保持在只读视图、验证链与学习层文档范围内。
- 窄屏与长模型的改进不得改变布局求解的确定性；不得引入像素快照或字体测量锁定。

## 5 P0 判定归属与状态一致性

本节三项已于 2026-11-03 实施。R01 落在 `correspondence.ts`、`CorrespondencePanel.tsx` 与 `ticket22`；R02 落在 `VerifyPanel.tsx`、`ticket24` 与 `ticket21` 的 F5 断言；R03 落在 `App.tsx`、`NarrativeView.tsx` 与 `ticket25`。浏览器验收见 `21-screenshots/`。

### R01 声明目标的单射探针与判定归属

**现象**

握手修正版第二条查询为非单射 `event(termClient(x,y)) ==> event(acceptsServer(x,y))`。验证面板判定“对应性成立”；对应性矩阵的同一“源码声明的安全目标”显示被证伪，详情写“源码声明的安全目标不成立，已被证伪，攻击路径见下方的反例 trace”。

**证据**

- 验证面板：`20-screenshots/u36-ns-verify.png`
- 矩阵选中态：`20-screenshots/u22-handshake-matrix-selected.png`
- 矩阵详情：`20-screenshots/u23-handshake-matrix-detail.png`
- 代码：`correspondence.ts:109`；`CorrespondencePanel.tsx:317-320`

**根因**

`createCorrespondencePlan` 对所有有序对统一生成 `inj-event(...) ==> inj-event(...)`。声明格与非声明格共用 `declared` 标记和 `declaredExplanation`，没有区分原查询与单射强化探针。ADR-0016 第 3 条要求详情注明“以单射形式强化”，当前实现缺少该提示。

**整改**

1. 在 `CorrespondenceQuery` 上增加判定语义字段，例如 `verdictSource: 'declared' | 'injective-probe'`；声明目标保留原查询文本与判定。
2. 对声明为非单射 `event` 的目标，矩阵声明格以原查询判定为准；单射探针另列，或只在详情中以“单射强化探针”出现。
3. `declaredExplanation` 只在原查询被证伪时使用“声明目标不成立，攻击路径见下方 trace”；探针被证伪时使用“单射强化探针不成立，不等价于原查询不成立”。
4. 详情并列展示“原查询判定”和“单射探针判定”，并给出二者语义差异的一句话说明。
5. 更新 ADR-0016 与 `CONTEXT.md` 的“声明目标”条目。

**验收**

- 握手修正版查询 2 的矩阵声明格显示“证明成立”，与验证面板一致；或同时显示“单射探针被证伪”与“原查询证明成立”，且明确说明二者不等价。
- 任何界面不得在未运行原查询的情况下，把探针的 `is false` 单独表述为“源码声明的安全目标被证伪”。
- 声明格详情保留源码原文；运行查询与原查询语义一致，查询前缀中的记号名可由工具规范化。探针查询另行标注。

**测试**

新增 `packages/web/test/ticket22-declared-correspondence-semantics.test.ts`。至少覆盖：非单射声明查询、单射声明查询、探针与原查询结论不同的合成输入。

**实施记录（2026-11-03）**

`CorrespondenceQuery` 增加 `declaredInjective`；`createCorrespondencePlan` 对非单射声明目标生成 `event` 查询，探索性有序对仍生成 `inj-event` 探针；`eventPairOfResultText` 同时解析 `event(` 与 `inj-event(`。矩阵说明与详情注明“按源码声明的非单射 event 查询判定；单射探针不属于本格结论”。验证结果：握手修正版两条声明目标均为“证明成立”，详情查询为 `event(termClient(x0,x1)) ==> event(acceptsServer(x0,x1))`。验收截图：`21-screenshots/p0-r01-declared-true.png`、`p0-r01-declared-detail.png`。

### R02 成立查询的 `goal reachable` 文案

**现象**

NS 原版查询 2、3 判定“证明成立”，卡片仍显示“ProVerif 报告该目标在攻击者模型下可达（goal reachable: ...）”。这是证明中的对应事实，不是攻击路径。

**证据**：`20-screenshots/u36-ns-verify.png`；代码：`VerifyPanel.tsx:247-251`。

**根因**

`view.goalReachable` 对所有判定方向无条件渲染，文案固定为“在攻击者模型下可达”。`query-presentation.ts:129` 对 `is true` 的解释是正确的，但 `goal reachable` 行没有同步分流。

**整改**

1. `is true` 时不显示该行，或改为“证明中给出的对应事实”，放入可折叠的“证明细节”。
2. `is false` 时保留该行，措辞改为“攻击路径摘要”，与下方 trace 形成一致层级。
3. 原始 `goal reachable` 表达式包含 `@occ`、`b-event` 等内部记号，不应直接占据主说明区。
4. 若用户需要核对原文，在“完整原始输出”中保留，不另行摘要。

**验收**

- 证明成立的对应性卡片不得出现“在攻击者模型下可达”。
- 被证伪的卡片可以出现“攻击路径摘要”，且与 trace 入口相邻。
- 原始 `goal reachable` 仅在折叠的“证明细节”或完整 stdout 中出现。

**测试**

新增 `packages/web/test/ticket24-verification-copy.test.ts`，断言真结果与假结果分别渲染不同文案。

**实施记录（2026-11-03）**

`VerifyPanel` 将 `goalReachable` 按判定分流：`true` 放入“证明中给出的对应事实”折叠项，`false` 显示“攻击路径摘要”；`ticket21` 的 F5 断言同步改写。验证结果：握手修正版查询 2、3 不再出现“在攻击者模型下可达”。验收截图：`21-screenshots/p0-r02-true-proof-detail.png`。

### R03 撤销人工配对后的状态清理

**现象**

撤销唯一一条人工配对后，端点已恢复未配对，配对清单已消失，画布上方的黄色提示仍显示“已声明配对：processB 发送 → processS 接收”。

**证据**：`20-screenshots/u42-pairing-stale-banner.png`；代码：`App.tsx:93-97`。

**根因**

`revokeManualIntent` 只清理 `manualIntents` 与选择状态，没有清理 `selectionNotice`。成功提示只在声明时写入，撤销时没有对应分支。

**整改**

1. 撤销时清空 `selectionNotice`，或写入“已撤销该条配对”的短暂提示。
2. 在黄色提示条内提供“撤销”入口；配对清单仍保留在画布下方，但不再是唯一入口。
3. 配对清单条目补充信道名，例如“信道 c2 · processB 发送 → processS 接收”，使多信道模型中可唯一指认。
4. 增加“全部清除”后的状态测试。

**验收**

- 撤销后提示条消失，或显示“已撤销”，且端点恢复未配对。
- 再次声明可正常写入，提示条重新出现。
- 配对清单与提示条对同一声明的描述一致，并包含信道名。

**测试**

新增 `packages/web/test/ticket25-pairing-feedback.test.ts`，覆盖声明、重复选择、撤销、全部清除。

**实施记录（2026-11-03）**

`App` 增加人工声明的信道记录；成功提示与配对清单均显示“信道 c2”等信道名，提示条提供“撤销上一条”。`revokeManualIntent` 与 `clearManualIntents` 同步清理 `selectionNotice`，撤销后提示与清单均消失，端点恢复未配对。浏览器验收：多信道样例 c2 声明后可即时撤销。验收截图：`21-screenshots/p0-r03-undo-entry.png`、`p0-r03-undo-cleared.png`。

## 6 P1 长模型可读性与交互

### R04 画布视口与嵌套滚动

**现象**

NS 修正版画布内容高度约 2469 px，可视区域约 608 px，首屏只能看到约四分之一。页面、画布与源码面板各自滚动，滚动上下文容易丢失。多信道与 NS 原版同样需要长距离滚动。

**证据**：`20-screenshots/u17-ns-mutual-1440.png`、`20-screenshots/u19-ns-mutual-1024.png`；代码：`v2.css:20-21`。

**根因**

画布容器固定 `max-height: 75vh` 并内部滚动。适合宽度只解决横向适配，没有提供纵向整页适配或全屏。滚动所有权虽已按 ADR-0015 分离，但长模型下缺少统一的“查看全图”入口。

**整改**

1. 增加“适合页面”与“全屏画布”两个显式入口；适合页面同时按宽高缩放，全屏提供最大可视区域。
2. 长模型允许画布高度随内容增长并由页面统一滚动，或保留 75vh 但把“适合页面”设为长模型默认。
3. 画布滚动条改为可见样式；滚动后保留缩放与滚动位置，切换协议时重置。

1. 面向用户只显示中文类别，不显示 `kind` 枚举；排查信息放入可折叠的“技术细节”。

6. 语法错误详情中的实际 token 改为行内 `code`，并附源码行片段，避免孤立 `)` 占一行。

**验收**

### R12 trace 与 stdout 的可操作性

### R20 事件旗标与源码行的键盘可达性

事件组有 `onClick` 与 `aria-label`，但没有 `role="button"` 与 `tabIndex`；源码行只有鼠标点击。端点与分支折叠已支持键盘，交互方式不一致。整改：为事件组补 `role="button"`、`tabIndex` 与 Enter/Space 处理；源码行提供 roving tabindex 或改为按钮语义；增加可见焦点样式。验收：只用键盘可选中事件、跳转源码、运行自反对查询。测试扩展 `ticket18-interaction.test.ts`。

**实施记录（2026-11-04）**

事件旗标（`structured-event--clickable`）、分支节点、本地/降级/insert 节点统一补 `role="button"`、`tabIndex={0}` 与 Enter/Space 激活（复用 `activateOnKey`，与端点、芯片、折叠开关的既有模式一致），Enter 与单击同一状态机（事件旗标同时触发矩阵选中与源码联动）。源码行实现 roving tabindex：仅当前行 `tabIndex=0`（默认第 1 行），↑/↓ 在行间移动、Home/End 到首尾，Enter/Space 触发与单击相同的反向联动；`.source-line:focus-visible` 显示左缘蓝色指示与浅底。画布三类节点补 `:focus-visible` 加粗描边。测试新增 `ticket18` 的 R20 三组断言（事件/降级/insert 节点 role 与 tabindex、roving 实现与焦点样式）。浏览器验收（握手修正版，纯键盘）：Tab/聚焦事件旗标后 Enter 触发矩阵行列高亮（2 个表头）；自反对查询按钮 focus + Enter 运行成功（详情显示）；源码行仅 1 行 Tab 停留、方向键与 Home/End 移动正确、在对象对应行 Enter 反向联动画布。验收截图：`21-screenshots/r20-keyboard-event-selected.png`。

## 11 风险与边界

1. **声明目标判定变更会改变矩阵结果。** 缓解：在 `ticket22` 中固定非单射、单射与混合输入；保留探针作为附注，不删除既有查询集合。
2. **适合页面可能进一步缩小文字。** 缓解：设定最小可读缩放；低于阈值时保持 100% 并允许滚动；全屏作为备选。
3. **标签翻转可能增加画布宽度。** 缓解：允许横向滚动，不压缩标签；为最左角色保留固定左槽。
4. **图例折叠可能隐藏信息。** 缓解：仅在值身份超过 12 个时默认折叠；保留展开、打印与灰度能力。
5. **移除内部枚举可能降低排查效率。** 缓解：把 `kind`、HTTP 状态码与代理细节放入可折叠的“技术细节”，不进入主提示。
6. **改写旧断言可能被视为降低覆盖。** 缓解：只改编码旧缺陷的断言，新增用例数不少于删除数，总用例数只增不减。
7. **ADR 修订可能影响既有验收。** 缓解：先提交 ADR-0015 修订、ADR-0016 修订与 ADR-0017，再改实现；在票据中记录差异检查。
