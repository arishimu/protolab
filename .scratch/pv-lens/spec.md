# pv-lens MVP：安全协议规范叙事视图 + ProVerif 验证

Status: ready-for-agent

## Problem Statement

学习密码学的学生、教师和研究者想弄懂一个安全协议：它「打算」怎么走、它声称的安全性是否成立、被证伪时攻击者到底怎么做到。今天他们只能对 `.pv` 文件手动敲命令行 `proverif`，再逐行读文本输出与自由项堆砌的反例 trace——门槛高，且「协议结构」与「验证结论」两张信息被割裂在两处。本仓库的 ProVerif 学习已完成（`docs/proverif/`），需要一个工具把这两件事接到一起。

## Solution

一个本地运行的 Web 工具（工作名 pv-lens）。用户导入或选择一个 `.pv` 文件后，浏览器**自动把它渲染成规范叙事视图**（每条角色一条泳道，泳道内按代码顺序列出消息步骤，词项符号化显示）；点一下「运行验证」，后端调用本机 ProVerif，前端把结果按查询逐条呈现——成立 / 被证伪，被证伪时附反例 trace 原文。解析不了的语法不崩溃，降级为原文标注段；ProVerif 缺失、验证报错、超时等都有友好中文提示。界面中文，代码与术语保留英文原文。

## User Stories

### 加载与选择

1. 作为用户，我想在首页看到内置协议列表，以便直接选择一个开始（不需要先懂命令行）。
2. 作为用户，我想从本地磁盘导入任意 `.pv` 文件，以便验证自己写的模型。
3. 作为用户，我想看到当前 `.pv` 的只读源码并知道它对应哪些解析产物，以便把「代码」和「图」对起来看。（编辑是二期能力，本版只读。）
4. 作为用户，我想随时切换回另一个内置协议，以便对比不同协议（含修正版 vs 含漏洞版）。

### 规范叙事视图渲染

5. 作为用户，我想看到每个命名进程成为一条泳道，以便一眼看出协议有哪些角色。
6. 作为用户，我想看到每条泳道内按代码顺序排列的消息步骤（方向：发出/接收、所在信道、词项），以便理解该角色依次做什么。
7. 作为用户，我想看到词项以密码学惯例符号化渲染（如 `encrypt((Na,A),pkB)` 显示为 `{Na,A}pkB`、`sign` 与 `aenc` 各有惯用记法），以便不被 `.pv` 语法挡住、直接读协议语义。
8. 作为用户，我想看到 `new` 生成的新鲜名在步骤中被标出（如 `new Na`），以便知道哪些值是本次会话新生成的。
9. 作为用户，我想看到 `event` 标注在相应步骤上显示，以便对应性查询能对应到协议位置。
10. 作为用户，我想看到 `if`/`let` 分支条件作为步骤注释显示在泳道内，以便不丢失守卫条件造成的分支语义。
11. 作为用户，我想看到 `!`（复制）与 `|`（并行）在该角色的表现上被标注，以便知道该角色可并发多会话。
12. 作为用户，我想在不能可靠确定「谁发出的消息被谁接收」时看到该步骤被明确标注为**未配对步骤**，以便不被臆造的连线误导（画对优先于画全）。
13. 作为用户，我想看到保守配对引擎确实配上的少数跨泳道连线，以便在可信处获得「A→B」的直觉。
14. 作为用户，我想把泳道图与源码逐行对应（点击步骤高亮对应源码行，反之亦然），以便把语法与语义互相印证。
15. 作为用户，我想看到泳道图在图例处解释各记法（符号化词项、未配对、复制标注等），以便自学时无需外部文档。

### 降级与诊断

16. 作为用户，当模型用到解析器不支持的语法时，我想看到它被降级为「原文标注段」留在泳道图里而不是让整个图失败，以便大协议仍能部分可视化。
17. 作为用户，当 `.pv` 有语法错误或解析失败时，我想看到带源码定位（行/列）的中文错误信息，以便定位问题。
18. 作为用户，当某个 `.pv` 完全没有可解析的角色结构时，我想看到明确说明而不是空白页面。

### 运行验证与结果

19. 作为用户，我想点一个按钮对当前 `.pv` 运行 ProVerif 验证，以便得到该模型的安全结论。
20. 作为用户，我想看到结果按**查询**逐条列出，每条显示：查询原文、判定（成立 / 被证伪 / 未能证明）、以及必要的解释，以便知道每一条性质各自的命运。
21. 作为用户，当某条查询被证伪时，我想展开查看**反例 trace 原文**（ProVerif 打印的完整攻击序列），以便研究攻击路径。
22. 作为用户，我想按需查看 ProVerif 的**完整原始输出**（可折叠），以便不依赖工具的解读做自己的核对。
23. 作为用户，我想在运行期间看到进度并可取消，以便误点或跑太久时能中断。
24. 作为用户，当本机没有安装 ProVerif（或找不到可执行文件）时，我想看到明确的安装指引与配置说明，而不是晦涩的报错。
25. 作为用户，当 ProVerif 报告模型自身错误（如类型错误）时，我想看到它返回的错误与源码定位，以便修模型而不是怀疑工具。
26. 作为用户，当验证超时时，我想看到超时提示并可调整时限，以便区分「模型太复杂」和「卡死」。
27. 作为用户，我想重复运行并在界面上看到最近一次的结果，以便修改后重新验证。

### 内置协议与教学

28. 作为用户，我想内置至少四个示范协议（hello 最小冒烟、握手修正版全绿、Needham-Schroeder 修正版互认证成立、Needham-Schroeder 原版含 Lowe 攻击），以便立刻看到「成立」与「被证伪」两种形态的完整例子。
29. 作为用户，我想在结果页看到对「成立/被证伪」含义的说明（`cannot be proved` 不等于不成立；查询显示为归一化形式），以便不误读 ProVerif 的判定方向。

## Implementation Decisions

- **模块划分**：三个模块——共享核心库 **core**（纯 TypeScript，浏览器与 Node 双端可用）、前端 **web**（React + Vite）、后端 **server**（Node）。core 不依赖任何 Node 或浏览器 API，作为 pnpm workspace 内包被 web 与 server 共同依赖。代码统一落在仓库应用根目录内，与 `docs/` 学习资料互不引用（样例文本在 core 内自成副本，不读 `docs/proverif` 的相对路径）。
- **core 公开能力**（功能级接口，实现细节见 tickets）：
  1. `.pv` → 语义模型：角色集合（含参数显示名）、每角色有序消息步骤（方向 / 信道 / 词项 / 事件标注 / fresh 名 / 复制与并行标注 / 守卫条件注释）、查询列表（保留用户原文）、降级诊断（指向源码 span + 原文片段）。语义模型只含展示所需的视图数据，不追求完整 ProVerif 类型语义（见 AD-0001 派生视图定位）。
  2. 词项符号化渲染：构造子 → 密码学惯用记法的映射表（加密/签名/元组/函数应用），未知构造子回退为函数调用写法。
  3. proverif stdout → 验证结果：按查询切段解析。
  4. 保守配对引擎：只在结构上可确定时产出跨泳道连线，否则不连（输出未配对标注，不猜测）。
- **stdout 解析事实**（已对本机 ProVerif 2.05 实测，解析器按此实现）：输出按查询分节——`Starting query <归一化查询>` 开头，若证伪则中间是编号反例步骤（`1.` `2.` …）与 attacker 事实，节末 `RESULT <归一化查询> is true|false|cannot be proved.` 一行收尾。`attacker(x)` 在输出中归一化为 `not attacker(x)`；判定值针对归一化查询，UI 展示时映射回用户查询原文。退出码为 0 并不代表性质成立（有反例也常是 0），判定只能以 RESULT 行为准。`cannot be proved` 目前四样例均不出现，但解析器必须支持。
- **验证接口**：web 把 `.pv` 文本 POST 给 server；server 经 CLI 适配器写临时文件并 spawn proverif，返回按查询的结构化结果 + 完整原始输出；超时与取消由适配器负责（AD-0002）。渲染路径不走 server：web 直接用 core 解析文本绘图。
- **CLI 适配器**（AD-0002 落点）：proverif 可执行路径可注入（默认读环境/配置）；区分三类失败：找不到可执行文件、proverif 自身错误（带输出）、超时。
- **错误分类**：解析降级（部分可读）≠ 解析失败（带 span）≠ 验证不可用（缺 proverif）≠ 验证报错（模型错误）≠ 服务不可达。各类别在 UI 有对应中文呈现。
- **内置样例**：四个基准样例，其 `.pv` 文本从学习归档 `docs/proverif/pv/` 复制进 core 作数据（副本为准，不读相对路径）。代号与源文件映射（实测核对过）：

  | 代号 | 源文件（`docs/proverif/pv/`） | 角色 |
  |---|---:|---|
  | hello | `hello.pv` | 最小冒烟；保密性破坏（RSA 明文出公开信道）|
  | 握手修正版 | `ex_handshake_annotated_fixed.pv` | 中例；对称/非对称/签名 + 事件，3 条全绿 |
  | NS 修正版（互认证） | `NeedhamSchroederPK-corr-mutual-auth.pv` | 大例；四角色，2 条全绿 |
  | NS 原版（Lowe 攻击） | `NeedhamSchroederPK-var1.pv` | 反例演示；endBparam 查询被证伪 |

- **UI 布局**：单页三区——源码（只读，可折叠）+ 规范叙事视图主区 + 结果面板；中文文案、术语与代码保留英文。泳道图由 web 自绘 SVG，不引入自动布局引擎（静态布局可控，拖拽编辑属二期，届时再评估图形库，见 Q7 决策）。
- **UI 措辞纪律**：所有「成立 / 被证伪 / 未能证明」措辞对照验证结论的归一化语义（如「证明成立」对应 `is true`）。

## Testing Decisions

- **好测试的定义**：只测 core 公共接口的外部行为——「文本进 → 结构化产物出」，不断言内部实现。fixture 驱动，黄金文件对比语义模型与验证结果的判定字段；不为凑覆盖率而测渲染像素或 spawn 细节。
- **Seam A（解析器）**：fixture = 四个基准样例的 `.pv` 原文。断言：角色集、每角色步骤序列（方向/信道/符号化词项串/事件/标注）、查询列表、降级诊断；另加手写的「不支持的语法 → 降级原文标注、不抛异常」与「语法错误 → 带 span 的诊断」用例。配对引擎并入此 seam 单测（只连确定边的保守用例 + 歧义不连的用例）。
- **Seam B（stdout 解析）**：fixture = **录制**的真实 proverif stdout。四个样例已实测（见 Further Notes 结果表），在开发时用本机 proverif 各跑一遍存档为 fixture，使 CI / 无 ProVerif 环境也能跑测试。断言：按查询切段数量、每条判定 true/false、证伪节的反例 trace 原文捕获、`cannot be proved` 的人工构造 fixture。
- **web 渲染层**：模型 → 布局坐标的纯映射函数做薄单测；整体只做冒烟级测试（四样例能渲染不抛错）。SVG 像素断言不做。
- **CLI 适配器**：与真实 proverif 的集成冒烟测试本地运行（含缺可执行文件、超时分支），不进 CI 必跑清单。
- **先例**：仓库暂无测试基建，本 spec 的 fixture 驱动风格作为先例；解析器与结果解析器的黄金 fixture 是后续协议样例测试的模板。

## Out of Scope

- 画布编辑（组件增删/拖拽/布局）与图 → `.pv` 回写——二期，入口见 AD-0001（改文本、重走管线）。
- 反例 trace 映射回泳道图的归因可视化——二期（Q6-c 决策）。
- 打包 / 分发 ProVerif 或应用容器化——决策已记 AD-0002，MVP 假设本机已装。
- 多用户、账号、云端持久化、公网部署。
- `.pv` 全语法支持：声明级可宽容解析，语义级只承诺教科书式顺序协议子集，其余降级为原文标注（不承诺正确建模 `choice`、观察等价等进阶构造）。
- 源码编辑、语法高亮补全、文件保存回写（编辑器属画布编辑二期）。
- 验证性能优化（四样例均毫秒级，当前无压力；超时保护存在即可）。

## Further Notes

- 词汇遵循 `CONTEXT.md`（规范叙事视图、角色、信道、消息步骤、词项符号化渲染、未配对步骤、查询、验证结论、反例/攻击 trace、画布编辑）；架构约束遵循 ADR-0001（文本为唯一真源、图为派生）与 ADR-0002（CLI 适配器、不打包）。
- 四基准样例实测结果（ProVerif 2.05，本机，全部 <20ms）——既是 fixture 断言基准，也是验收口径（源文件在 `docs/proverif/pv/`，见 Implementation Decisions 的映射表）：
  
  | 样例（源文件） | RESULT（归一化查询） |
  |---|---|
  | hello（`hello.pv`） | `not attacker(RSA[]) is false`（保密性破坏，含 trace）；`not attacker(Cocks[])` 对应结论成立 |
  | 握手修正版（`ex_handshake_annotated_fixed.pv`） | 3 条全部 `is true` |
  | NS 修正版互认证（`NeedhamSchroederPK-corr-mutual-auth.pv`） | 2 条全部 `is true` |
  | NS 原版（`NeedhamSchroederPK-var1.pv`） | 共 6 条：`inj-event(endBparam(x)) ==> inj-event(beginBparam(x)) is false`（Lowe 攻击，含 trace）；`inj-event(endAparam(x)) ==> inj-event(beginAparam(x)) is true`；`not attacker(secretANa[])` / `not attacker(secretANb[])` 均 `is true`；`not attacker(secretBNa[])` / `not attacker(secretBNb[])` 均 `is false`（B 侧泄密，亦含 trace） |

- 验收即「四样例在图与结果面板上都呈现正确」（含一处降级/未配对路径演示）。
- 本 spec 由 `/to-spec` 从 grill-with-docs 访谈产出，后续由 `/to-tickets` 拆 tracer-bullet 工单，每张带阻塞边，逐张 `/implement`。

## Comments

### 验收记录（/implement #09，2026-09-18）

**环境**：ProVerif 2.05（`~/.opam/default/bin/proverif`）· Node 26 · 基线 commit `791b3ee`。

**方法**：`pnpm build` 后启动 `node packages/server/dist/index.js`（127.0.0.1:8787）与 `vite preview`（127.0.0.1:4173），用真实无头 Chromium 在浏览器里逐样例走「装载 → 渲染 → 运行验证 → 核对结果」；另用 `pnpm typecheck` + `pnpm test`（195 项）护航。

**四样例实测结论**（浏览器内：泳道图 + 判定徽标 + 反例折叠 + 完整 stdout 四方核对）：

| 样例 | 泳道 | 渲染要点 | 本次实测证据 |
|---|---|---|---|
| hello | `main`（无命名角色） | RSA 明文步骤 + 符号化词项 | 2 条判定；被证伪那条反例 trace 374 字符 |
| 握手修正版 | `clientA`、`serverB` | `{[pkX,pkB,k]skB}pkX`、`{|s|}k` | 3 条判定 |
| NS 修正版 | `processInitiator`、`processResponder`、`processS`、`processK` | 四泳道 | 2 条判定 |
| NS 原版 | `processA`、`processB` | Lowe 攻击样例 | 6 条判定；三条被证伪的 trace 4320 / 3896 / 4149 字符 |

上表的判定结果与 Further Notes 的实测结果表**逐条一致**（不自维护一份副本，以那张表为准）。

**与录制 fixture 的一致性**：四样例的完整 stdout 与 `packages/core/fixtures/proverif/*.stdout.txt` **逐字一致**；三条被证伪查询的反例 trace 文本与 fixture 解析出的 `counterexampleTrace` **逐字一致**（浏览器内展开折叠块后比对；仓库侧回归见 `core/test/verify-result.test.ts` 的切片对照）。

**降级 / 未配对路径**：

- 未配对：握手修正版默认 6 个步骤标「未配对」，跨泳道连线 0 条（保守配对不臆造），图例在位。
- 降级：导入含 `choice [true]` 的 `.pv` → 面板提示「解析器不支持的语法」、泳道图保留 `choice [true]` 原文标注段；验证仍按原文运行并给出失败指引。

**发现与处置**：验收未发现功能缺陷。仅发现一处文档口径问题：本 spec「stdout 解析事实」写的 `RESULT <查询> is true|false|cannot be proved.` 暗示存在 `is cannot be proved.` 形态，而本机 ProVerif 2.05 的 `cannot be proved` 真实输出不带 `is`（`RESULT <查询> cannot be proved.`，`noninterf` 查询可复现）——该差异已在 `packages/core/fixtures/PROVENANCE.md` 记录，解析器两种形态都兼容（`core/test/verify-result.test.ts`）。spec 该行措辞留待 #10 文档收尾统一。其余交付项（README 安装运行说明、工程收尾）同样由 #10 承接。

**自动测试现状**：`pnpm typecheck` 三包通过；`pnpm test` 16 文件 195 项通过（含真实 ProVerif 集成冒烟，本机装 ProVerif 时运行）。
