# event 旗标与 O(n²) 对应性查表的交互

Type: prototype
Status: resolved

## Question

`event` 做成生命线上的专门标记（旗/菱形）。交互：用户**依次点击两支旗**，展示该事件对的对应性查询结论，不画虚线。

已定实现口径：预跑**全部有序对** `inj-event(eᵢ) ==> inj-event(eⱼ)`（同参数共享），缓存后点击查表。

要定的是交互与呈现：旗标形状 / 可点性 / hover、两次点击的中间反馈、命中与未命中的呈现、结果放哪（侧栏 / 内联）、n 稍大时怎么组织。素材 `ns-original`（含 `beginBparam` / `endBparam` 等）。

## Notes

来自 issue 06 的实测制约：生成的 query **必须插在 `process` 关键字之前**，不能追加到文件末尾。详见 [`research/06-proverif-batch-queries.md`](../research/06-proverif-batch-queries.md)。

## Answer

HITL 原型定稿（用户对三变体原型 + 一轮 grilling 的反馈）：

**标记形状与选择语义**

- 事件标记为**菱形**（空心 teal）；不另设形状开关。
- **前提端**：仍为菱形，仅填充强调 + 光环。**结论端**：换成**实心圆点 + 斜插旗帜**（旗面朝图外侧）；旗杆**加长**，旗面为**等腰三角形**——底边与旗杆重叠（共线）、且与旗杆顶点对齐，三角形尖端朝图外侧。两端因此在图上可直接分辨，不靠结果文字里的 `⇒`。
- 依次点两支旗：第一支 = 前提（inj-event 左侧），第二支 = 结论（右侧）。**同一支旗点两次 = 自反对查询**（`inj-event(e) ⇒ inj-event(e)`），不视为取消。
- hover：标记放大（内层 group `scale(1.22)`）+ tooltip 显示 `event name(args)`，同时状态行预览「点击设为前提端 / 结论端」；**不做 hover 即查**。`Esc` / 点空白重置。

**结果呈现（A + C 结合）**

- **A 内联查询气泡**：查询完成后贴在**结论端**标记下方，含两端的 `event(args)`、判定 badge、生成的 query 原文、一行判定说明。
- **C n×n 对应性矩阵**：常驻右侧可开合面板；行 = 前提、列 = 结论；全部有序对一屏，n=8 仍可定位。**矩阵点格与图上点旗双向联动**。
- 砍掉「侧栏查询簿」（B）：历史价值低、常驻占宽。
- 选中格及其**所在行 / 列**的高亮**用该格判定色**（绿 / 红 / 黄），不用黑色；**选中格符号加粗放大**（✓ / ✕ / ?）。
- 命中 / 未命中措辞遵循 `CONTEXT.md`：**证明成立** / **找到反例** / **未证出**（不用通过 / 失败）。

**数据与语义提示**

- 详情**原样展示实际生成的 query 原文**（`query x: T; inj-event(Ei(x)) ==> inj-event(Ej(x)).`），方便贴回 `.pv`；参数不完全对应（存在量化退化）的提示留作后续讨论，本轮只展示原文。
- **保留反例 trace 入口**：`false` 时在详情里给「查看反例 trace」按钮，点开为内联占位块；真实 trace 来自 `parseVerifyStdout` 的 `counterexampleTrace`，完整反例 / 执行视图仍属独立 effort（本 effort out of scope）。

**素材与实测**

- `ns-original`（4 events）用**真判定表**：本次实跑 ProVerif（生成的 query 插在 `process` 之前，退出码 0）得 16 条有序对——`diag=true`（4）、`endAparam⇒beginAparam=true`、`endBparam⇒beginBparam=false`（Lowe 攻击对应的认证失败），其余 false。
- 另加合成 8 事件样例（示意值，含 1 个 `cannot be proved`）用于看 n 稍大的组织。

**资产**：`prototype/04-event-flag-lookup.html`（自包含单文件，双击浏览器打开；画法对齐 `prototype/03-value-layer-refined.html`）。

**残余**：参数共享退化为存在量化时的界面提示方式，待后续 ticket / 实现阶段再定（不影响本 ticket 的交互结论）。

### 第二版修正（用户复看原型后的反馈）

1. **叙事视图在 `prototype/03-value-layer-refined.html` 基础上重绘**：值方块（一色一值）、方法盒、信道紫框词项、同色复制、箭头指向接收端、虚线生命线全部沿用 03 的画法；event 标记叠在其上。素材改用 **ns-original 完整值层链 + 4 个 event**（`beginBparam`/`endAparam` 在 A，`beginAparam`/`endBparam` 在 B），另以同骨架的 synthetic-8 看 n 稍大。（ns-mutual-auth 的值层密度演示仍归 02/03 的资产，本 ticket 不重复画。）

**资产**：`prototype/04-event-flag-lookup.html`（自包含单文件，双击浏览器打开；经运行时自检：4 / 8 事件两个样例均能渲染，标记、矩阵高亮与气泡均正确）。
