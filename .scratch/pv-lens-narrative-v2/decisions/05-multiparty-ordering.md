# 多方无配对时的纵轴语义

Type: grilling
Status: resolved

## Question

ADR-0003 下多方协议（`ns-mutual-auth` 4 角色）不做意图配对。v2 的纵轴是「消息序」，但没有配对就无法推断跨角色的全局消息序——纵轴退化成什么？

已接受的态度：多方消息挂在信道轨上、不画角色间连线。剩下要决定的是**纵轴**：用某角色的本地代码序？按源码行交错？还是多方退回「无共享行」的局部模式？这直接决定旗舰四方样例在 v2 里长什么样。

## Comments

**Claimed**（本次会话）。已核对的事实（供决策，非结论）：

- `ns-mutual-auth.pv` 有 **4 个命名角色**（`processInitiator` / `processResponder` / `processS` / `processK`），外加一个 `process` 主进程伪角色（`new skA/skB/skS` + `out pkA/pkB/pkS` + `insert keys`）；消息步骤约 16 条，全部未配对。
- `ns-original.pv` / `handshake-fixed.pv` 均为 **2 个命名角色 + main**；`pairSteps` 只数命名进程（`narrativeRoleOrder`），故这两份仍走共享行。`hello.pv` 无命名角色（只有内联主进程，1 条 `out`）。
- 源码里**只有 `ns-mutual-auth.pv` 写了 `(* Message 1…) (* Message 7 *)` 注释**，且只在「真实消息」步骤上：同一条消息的 out / in 两侧编同一个号（如 I 的 `out m3` 与 R 的 `in m` 都是 Message 3）；而角色启动步（I 的 `in(c,(xA,hostX))`、R 的 `in(c,xB)`、S 的 `in(c,(a,b))`）**没有编号**。`ns-original` / `handshake-fixed` 无任何 Message 注释。
- 现有 `pairSteps` 的形状/类型匹配（`matchesIntent`）在多方下返回空集（ADR-0003），但它本身可作为「词项依赖」的原料。

## Answer

HITL 定稿（三轮 grilling）：

**多方（命名角色数 ≠ 2）下纵轴退化为「局部梯子」：不做全局线性化，每个角色保留自己的本地消息序，唯一共享的空间锚点是信道（归属）；角色之间不再承诺行对齐。** 在此之上给**未配对步骤**一个出口：**人工上下移动 → 人工配对**，把全局叙事交还给掌握协议知识的用户。

1. **默认 = 局部梯子。** 多方下**不推断**全局消息序——否决「词项偏序推断」与「源码/索引硬线性化」：静默推断正是 Destination 头号问题「时间错觉」，且 ADR-0003 已判多方路由不可静态推断。代价照单全收：默认态下 `ns-mutual-auth` 是「四条并排本地流 + 一条共享信道轨」，而不是一条 7 步叙事。
2. **边界沿用现口径。** 只数命名进程（`narrativeRoleOrder`）；`≠ 2` 即多方并触发降级；`main` / 内联主进程不计入，无命名角色时整体作单条伪角色；`!` / `|` 不改角色数。恰好 2 个命名角色 + main 仍走共享行。
3. **人工配对（本票新增的出口）。** 任意**未配对步骤**（不限多方）都可被用户上下移动；把两个不同角色的未配对步骤对齐 = **人工声明它们是同一条消息**，视图画成一条完整消息行，并标记「人工」以区别于自动配对。
   - **表达 = 行序约束，不是像素 y。** 拖拽只声明「同一条消息 / 同一行」，并据此在本角色局部序中重排该步骤；具体 y 交给 ticket 08 的间距解算器（复用其「配对消息处的跨角色耦合」）。ticket 08 需接受「外部同序约束」输入。
   - **合法性。** 跨信道**硬禁止**（吸附只在同信道内）；一对多 / 多对一**禁止**（一对一，重复占用高亮冲突）；类型 / 形状不符**只警告不阻断**（那是自动配对的判据，不是用户的判据）；成环 / 与局部序矛盾**不静默重排**，显式标「冲突」由用户撤销或修正。
   - **状态形状。** 人工配对存成**声明式「意图边」列表**，与自动配对**共用同一 IR**；锚点 = `roleName + direction + 角色内序号`（附源 span 校验），**仅会话内存**。这份列表就是未来画布编辑要回写 `.pv` 的内容来源——本轮只保证形状不挡路，持久化 / 回写归二期（画布编辑，Out of scope）。
4. **术语与 ADR。** `CONTEXT.md` 新增「人工配对」「局部梯子」并修订「意图配对 / 未配对步骤」；新增 `docs/adr/0005`，记录「多方**自动**配对仍关闭、可由用户**人工**声明」对 ADR-0003 的边界修订。
5. **后续票**：新建 prototype 票承载交互与视图状态（`09-manual-pairing.md`）。
