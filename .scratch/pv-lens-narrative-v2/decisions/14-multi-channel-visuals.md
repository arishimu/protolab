# 多信道视觉

Type: prototype
Status: resolved

## Question

四个内置样例的信道**全部是 `c`**（已核实），`ns-mutual-auth` 是单信道多方。01–09 的信道规则（总线方块、信道色配对箭头、跨线弧、未配对挂轨、同侧 jog、按信道匹配的自动配对）都只在**一条**信道下验证过。要 prototype 定稿多信道（2–3 条）下的视觉语法与适配：

- **区分手段**：线型 / 颜色 / 图例 / 轨道分组 —— 哪种在「只有一条信道」时不退化、在三条时仍一眼可辨？颜色现在有**三套语义**在抢：**消息身份色**（一条消息一种颜色，见 `docs/adr/0008`）、值层的「一色一值」**值身份色**、以及**信道色**——三者如何共存 / 分层 / 让位？
- **信道形态**：多信道时是**并列多条总线方块**，还是同一总线按信道分色 / 分道？
- **既有规则的改写**：跨线弧（01）、未配对挂轨（ADR-0003）、配对箭头用信道色、同侧 11px jog（09）在多信道下各自怎么改；人工配对「同信道」这一硬约束在分道后是否仍然够用。
- **图例与联动**：要不要信道图例；与「跑验证」结果面板、未配对列表的关系。

交付物含 **`fixtures/pv/multi-channel.pv`**（>1 条信道，最好覆盖跨信道并行 / 一条信道多方 / 一条信道只有未配对步骤），并核对该 fixture 在解析器与配对引擎下不崩（若发现缺口，就地记进本票 Comments，**不另开实现票**）。

判据：读者能一眼分辨「这条消息走哪条信道」「哪些端点是同一信道上的对端」，且单信道样例的观感不变。

## Answer

**定稿变体 A：信道不占颜色，颜色让给消息。**

- **信道身份 = 几何**：ADR-0009 水平序列里的**位置** + **序号字形**（① ② ③）+ **总线方块边框线型**（实线 / 长虚 / 点线）；多信道 = **并列多条中性总线方块**，否决「同一总线分道」（变体 C）。
- **颜色只留给两层**：**消息身份色**（一色一消息，画在消息柱 / 消息段 / 箭头）与**值身份色**（一色一值，画在值方块）；靠画法载体（线 / 柱 vs 块）共存。
- **保留**：跨线弧（ticket 01）；未配对端点 = **橙色开放圆点**落在其信道总线壁上（橙色不作为信道色）；单一信道退化为「一条中性总线 + 消息色 + 值色」，观感不变。
- **同信道硬约束不变**（本票已用 2 角色 / 2 信道核对：`out(c1)` 只配 `in(c1)`、不与 `in(c2)` 配）。
- 原型 `prototype/10-multi-channel-visuals.html`（A/B/C 三变体，A 为定稿；B/C 留作 primary source）；fixture `packages/core/fixtures/pv/multi-channel.pv`。
- 新增 `docs/adr/0010-multi-channel-geometric-identity.md`；`CONTEXT.md`「消息身份色」词条同步收口（「信道色」列为避免用词）；ADR-0008 遗留段落回指 0010。
- 残留（交 `/to-spec`，不另立票）：消息色板 / 值色板的具体取值与同屏可区分性；信道图例与「跑验证」结果面板 / 未配对列表的关系；缩放 / 滚动、与源码面板的联动。
