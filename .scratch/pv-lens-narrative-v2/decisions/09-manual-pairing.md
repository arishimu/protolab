# 人工配对：点选声明 / 广播扇出 / 接收端多行梁

Type: prototype
Status: resolved

## Question

（来源：`05-multiparty-ordering.md` 的定稿）多方（命名角色 ≠ 2）默认走「局部梯子」——不做全局线性化，角色间不共享行。给未配对步骤一个**人工配对**出口：用户上下移动一条未配对步骤，与另一角色的未配对步骤对齐 = 声明它们是同一条消息。

要 prototype 定稿的是**交互与视图状态**：

- 拖拽 / 上下移动的具体交互：吸附判定、吸附目标提示、移动中反馈、撤销 / 重置；
- 本角色局部序的重排与预览（行序约束语义；y 待 ticket 08 解算，原型可用临时算法）；
- 「人工」标记与冲突标记的视觉：跨信道禁止、一对多禁止、类型 / 形状不符仅警告、成环 / 与局部序矛盾显式标「冲突」；
- 声明式意图边列表（与自动配对共用 IR）在界面上的可见形态（图例 / 列表 / 角标）；
- 四方样例 `ns-mutual-auth` 从「四条局部流」过渡到「一条 7 步叙事」的观感与操作成本。

## Answer

**HITL 定稿（三轮反馈；用户确认「确定」）**：人工配对的交互与视图状态如下，原型 `prototype/06-manual-pairing.html` 为准。

### 1. 交互（画布点选，无拖拽）

- **点一个端点选中，再点另一个端点即声明配对**；非法点击当场给原因并改选新端点。
- **一对多 = 重复点选同一个源**：先点 `s1`、`s2`，再点 `s1`、`s3`。发送端可接任意多个接收端，**无上限**、无「服务端角色」提示。
- 选中态把所有兼容目标亮环（蓝 = 可配、琥珀 = 形状 / 类型不符但仅警告）；点已配对端点可查看 / 解除。
- **不提供拖拽**；**不提供局部序 ↑↓ 重排**。撤销（Ctrl+Z）、重置保留。

### 2. 一对多 = 一次广播（扇出），不是多条相同连线

- **一行 = 一次广播**：按**发送端**归组，一个 `out` + 它的全部 `in` 合成一行；**一条发送段进信道 + N 条接收段出信道**，同一 y，角标 **`广播 ×N`**。`ns-mutual-auth` 的 `s_out2 → {i_in2, r_in5}` 即一行（Message 2 & 5 合成一条广播行）。
- **接收端被多条消息收到**（`s_in1` 收 Message 1 与 4）：它在多行各出现一次，用竖向 **「收到 ×N」梁**连起来（与「一对多发送」区分：发送端永不占多行）。
- **值层 / 事件 / 本地步骤只留文本刻度**（值层归 ticket 02/07）；广播行内多个接收端各自的本地内容仍贴各自角色列。

### 3. 合法性与冲突

- 硬约束：跨角色、`out × in`、同信道、不重复声明；**复用不限量**。
- 类型 / 形状不符：**仅警告不阻断**。
- **广播 · 跨序 = 合法态**（琥珀，非错误）：广播行的时间位置与某角色的本地序冲突时，布局**自动拆环**（拆掉指向广播行的矛盾边）、把广播行移到自洽位置并标 `广播 · 跨序`；真实环（不涉及广播行）仍标红「冲突」，显式不静默。`ns-mutual-auth` 最终顺序：M1 → 广播(M2/M5) → M3 → M4 → M6 → M7，另 4 个未配对端点。
- **放宽口径**：本条修订 ticket 05「同一条消息 = 同 y」与 ticket 08「同 y 硬约束」——**广播行**允许「一条消息跨越多个角色时间点」。

### 4. 角色相对信道的位置 + 同侧去重叠

- **按通联图二分割**角色到信道两侧：把消息数最多的角色单独一侧（本例 I 在左），其余放另一侧（R/S 在右），K 放最外；**最忙的角色贴总线**。数组顺序仍是源码角色序 `narrativeRoleOrder`，`x` 只决定画在哪。
- **收发同侧**时（本例只剩 R–S）：接收段在总线边**竖向分叉并逐级下移 11px**，避免与发送段共线重叠。

### 5. IR 与资产

- 人工配对仍产出 `MessagePairing { outEnd, inEnd, origin: 'manual' }`，与自动配对共用 IR；**广播分组是视图层的派生**，不进 IR。仅会话内存，不回写 `.pv`。
- 资产：`prototype/06-manual-pairing.html`（自包含；`?preset=1` 预置 7 条意图边）。
- **ADR 修订**：新增 `docs/adr/0007-broadcast-fanout-manual-pairing.md`，把 ADR-0005 的「一对一禁止」修订为「允许一对多广播扇出」，并记录广播行 / 收到梁 / 跨序合法态 / 角色分配 / 同侧 jog。

### 6. 残余（交回 map 的 Not yet specified）

- 广播行内多个接收端的**值层与事件标记**如何与行 y 对齐（同一 y 还是各贴本地位置）。
- **通用角色左右分配算法**（通联图二分割 / 最小化同侧消息数 / 最忙贴总线）目前是**手工**按样例分的。
- 「收到 ×N」竖梁在接收端很多时的**堆叠上限 / 折叠**。
