值层画法对比原型：A 内联记号 / B 独立 ledger / C 派生盒

throwaway prototype · wayfinder ticket 02 · 假数据，未接真实解析器

问题：消息层与值层分离后，每角色本地记号（m/NY/Na/NX…）画在哪、let (=Na, NX) = adec(m, skA) 的派生怎么画成边、=Na（等值检查）与 NX（新绑定）如何在视觉上区分。

判据：读者能否顺着派生边看出「收到的东西怎么变成下一条发出去的东西」；值层在 ns-mutual-auth 密度下是否仍可读。

三种画法：A 值节点挂在生命线外侧 + 派生箭头；B 值层独立成每角色的「值流 ledger」；C 派生算子是带端口的盒。用下方素材切换两方核心链 / 多方密度链。

素材

变体 A · 值节点内联（挂生命线外侧）+ 派生箭头

记号是小圆角片，新绑定 = 青实心、接收绑定 = 灰实心；adec 在生命线上画一个菱形算子，从收到的 m 拉派生箭头扇出到产物；=Na 是红色虚线回指原 Na 片并带 ✓。点虚线 = 「该记号被用作某条发出消息」。

■ 新绑定　■ 接收绑定　┈ =等值检查（回指 + ✓）　→ 派生边　┈ 用于发出消息

变体 B · 值层独立成「值流 ledger」（消息梯子保持干净）

梯子只画消息 + 本地点 + 事件，值记号全部下沉到下方每角色一条的值流带里，按引入顺序横排；派生画成带内箭头，= 检查是带内红色回弧 + ✓，记号上方 ▲ 表示「被用于发出」。

■ 新绑定　■ 接收绑定　⌒ =等值检查（回指 + ✓）　→ 派生边　▲ 用于发出

变体 C · 派生盒（端口式）

把 let ... = adec(...) 画成生命线上的一个小盒：左端口进 m、右端口出产物；新绑定从普通端口拉出青色片，= 检查是 ⊕ 端口 + 红色虚线回指原记号。

■ 新绑定　■ 接收绑定　⊕ ┈ =等值检查端口（回指）　→ 端口线　┈ 用于发出
