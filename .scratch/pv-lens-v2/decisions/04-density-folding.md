# 密度与折叠

Type: prototype
Status: resolved
Blocked by: 01

## Question

梯子 + 值层 + 本地节点会让图变高（`ns-mutual-auth` 4 角色）。定稿默认密度策略：

- 本地步骤（`new` / `let` / `if` / `get` / `insert`）默认折叠，hover / 点击展开；消息与 event 始终可见。
- 角色可整体折叠。

需要回答：折叠的实施形态与成本（用户担心实现难度）、折叠后的视觉提示、与值层派生边的交互（边被折起来怎么显示）。

## Answer

HITL 定稿（用户对三变体原型 + 一轮 grilling 的反馈，原型 `prototype/05-density-folding.html`）：

**策略 = A 为骨架 + B 的 hover 浮卡 + 折叠时保留下游值块（幽灵块）。** C 的角色整体折叠**不做**（成本最高、收益最不稳，且与 ticket 08 强耦合）。

1. **折叠 = 默认显示状态**，不是空间不足时的压缩手段。原 ticket 正文的「本地步骤默认折叠」与 ticket 08 Notes 的「折叠是最后手段」是两件事：默认显示密度由本票定（本地步骤默认折叠成折叠块），空间不足时的压缩次序归 ticket 08（`gap.group → gap.row → gap.tight → 禁止动簇内`）。规格里必须分开写「折叠 ≠ 压缩手段」。
2. **折叠粒度 = 整个算子簇折成一格**（输入方块 + 算子盒 + 输出方块一体；与 ticket 08「簇内紧贴永不变」一致）。不是只折本地语句标签。
3. **折叠后的值层 = 保留下游还要用的值**，以**虚线幽灵值块**呈现（需 ticket 07 的「谁引用了谁」数据）。不采用「值方块全留」（几乎无压缩收益），也不采用「值层整层隐去」（破坏同色垂直追踪这个承重墙）。
4. **角色折叠 = 只隐藏该角色细节，不动行距**；行距压缩统一归 ticket 08 求解，避免两票各算一套间距。
5. **两条实现形态要求**（用户补充，已落入原型）：
   - 幽灵值块放在**折叠块的下面**，表明「这些值是折叠步骤产生的」；
   - 折叠块**表面直接显示内含的算子名**（如 `▸ adec +2`、`▸ split·insert +2`），不写「▸ N 步」。

实现成本口径：A + 幽灵值块为中成本（依赖 ticket 07 的引用数据 + 展开时纵向重排；hover 浮卡不触发布局）。未做：算法化间距（ticket 08）。
