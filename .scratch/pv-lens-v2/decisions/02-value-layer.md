# 值层：值节点与派生边的画法

Type: prototype
Status: resolved
Blocked by: 01

## Question

消息层与值层分离后，值层怎么画：每角色本地的记号（`m`、`NY`、`pkY`、`Na`、`NX`）作为节点挂在哪，`let (=Na, NX) = adec(m, skA)` 这类派生怎么画成边，`=Na`（等值检查）与 `NX`（新绑定）如何在视觉上区分。

对照 `ns-original` 的两处关键链条：A 侧 `new Na` → 发 `{Na,…}` → 收 `m` → `=Na` 检查；B 侧 `in m` → `adec` → `(NY,pkY)` → 发 `{(NY,Nb),…}`。

判据：读者能否顺着派生边看出「收到的东西怎么变成下一条发出去的东西」；值层在 `ns-mutual-auth` 这种密度下是否仍然可读。

## Answer

**定稿（HITL，用户判定）**：以**变体 C（派生盒）**为基底，按下述规则落地值层画法。

- **值方块镶嵌在生命线上**，一种颜色 = 一个值（**颜色即值身份**）。已知值（角色参数 `skA`/`pkB`…）排在生命线开端「参数」区；`new` 产生新值处出现方块；接收值方块嵌在接收点（也是消息箭头指向处）。
- **方法 = 白底黑字的倒置等腰梯形盒**（上底更宽、下底更窄；**短底 = 值方块宽 50px**，与上下紧贴的方块对齐；见第四轮修正）：算子名写在盒内；**输入方块紧贴上方、输出方块紧贴下方**。
- **输入复制引用的方块**（同色同名的副本）；**等值测试输出也是直接复制对应方块**——「同色再现 = 同一值 / 等值检查」，「新颜色 = 新绑定」。不用红虚线、不用 ✓、不用任何专用等值符号。
- **去掉派生边与「用于发出」连线**：不再画记号之间的箭头，追踪完全靠**同色方块的垂直编排** + 后续消息紫框内的词项名。这是本轮为解可读性（原变体 A 线混杂）而做的核心删减。
- **消息实际词项只在信道紫框内显示一遍**（不再在收发两端各写一次）。
- **消息三角箭头从信道指向接收端**（原实现方向相反，已修正）。
- 视觉微调：方块等宽 50px、输入/输出中心距 20px、组间距拉大、可延长生命线。

**原型留档**（throwaway primary source，不并入 main）：`prototype/02-value-layer.html`（三变体对比）、`prototype/03-value-layer-refined.html`（定稿版）。

**未决残余**（本票未决定，已记入 map 的 Not yet specified）：`if` 守卫（`if pkX = pkB` / `if Nb = adec(m3)`）与纯构造方法（`encrypt` / `sign` / 元组构造）在值层里怎么呈现——是否沿用同一套「方法盒 + 同色复制」，还是区分「解构」与「构造」。
