## Question

值层定稿了「方法盒 + 同色复制」这一套画法，但它只覆盖**解构**（`adec` / `sdec` 等）。要 prototype 定稿两类今天没有画法的东西：

2. **纯构造方法**：`encrypt` / `sign` / 元组构造这类「只构造不解构」的算子，是沿用倒置等腰梯形方法盒（短底 = 值方块宽 50px），还是与解构盒区分（形状 / 底色 / 箭头方向）？「构造出新值」与「新绑定」在视觉上如何不混。

判据：`ns-original` 的两处守卫 + 构造链在画布上不误导「检查的是哪个值」「走的是哪条支路」；`ns-mutual-auth` 的密度下守卫不把生命线挤爆。

## Answer

**定稿（HITL，两轮 grilling，用户全部采纳推荐）**。画法如下；原型 = `prototype/08-conditional-constructors.html`（默认变体 D「定稿组合」）。

### 1. 守卫 = 等值检查盒（原 C）

- 守卫（`if` 条件与 `get` 表模式）画成竖栈里的一个**等值检查盒**：倒置等腰梯形、**无输出**，与 02 的方法盒同形状族——它是一次「判断」，不产出值。
- 被检查的两个操作数 = **紧贴盒上方的两个同色方块**（同色 = 同一值，沿用 02 的复制口径）；op 写在盒内：`=` / `<>`（`if`）、`∈`（`get 表模式`）。
- **条件里内嵌解构**（`if Nb = adec(m3,skB)`）：内嵌的 `adec` 自己画成一个解构盒，其输出是**派生虚线芯片**（不是值方块）喂进检查盒。
- **复合条件**（`&&` / `||`）：每个子句各占一行检查行，连接词作字形放在行间（对照侧），**不加括号节点**（沿用 12 的 `clauses` 嵌套）。
- 守卫盒落在**主生命线**上、分叉之前（两操作数都在主路径作用域内可见）。

### 2. 两臂 = 并行臂道（原 A）

- `then` = 第 1 条臂道、`else` = 第 2 条，各有一条竖直虚线轨从 `branch` 到 `join`；分叉与合流处用横tick 接回生命线，道顶部标 `then` / `else`。
- **`then` 臂恒偏移一条道**（无 `else` 的单臂 `if … then …` 也偏移）——否则单臂分支从画布上看不出范围。
- 臂道号 = `1 + 外层 else 数`；同层顺序出现的两个分支共用同一道（不错位）。
- **封顶 2 道**：第 3 层及更深的 `else` 嵌套不再让道，改为道内**缩进 + 嵌套角标**（`↳` / `+1`）。
- `branch…join` 整段 = **08 的刚性计算单元**（像 10 的扇出团）：内部间隙固定、整体平移；臂道只改 `x`，不影响 08 的间隙解算。
- **默认不折叠**：分支是刚性单元但默认展开；折叠只作可点开关（非默认态）。理由：守卫的语义就在它管辖的那几条步骤里。

### 3. 空臂（`else 0`）

- 显示 `else` 道的一个**空桩**：一小段橙轨 + `∅`，不画任何步骤；以此把「有 `else` 但臂为空」与「根本没 `else`」分开。

### 4. 构造 vs 解构 = 方向

- **同一个倒置等腰梯形**（短底 = 值方块 50px）用于两者；只靠**方向**区分：解构**竖向**（信道 → 生命线）、构造**横置**（生命线 → 消息）。
- 不用形状 / 底色区分：颜色已被「值身份色 / 消息身份色 / 信道色」三套占满（ticket 14 收口），不塞第四套语义。

### 5. 「新值」vs「新绑定」

- **只有绑定拿值方块**（新色，= 值身份）；未绑定的内联构造（直接写在 `out` 里的 `aenc(...)`）结果是**虚线 wire 词项芯片**，**不发新颜色**，以免被误读成值身份。

### 6. 条件表达式 = 选择盒（`PvTerm.conditional`）

- `let x = if c then a else b` 也沿用倒置等腰梯形：盒内写 **`?:`**（短、不像算子名），输入 `a` / `b` 在上、输出 `x` 在下，条件 `c` 作**外侧芯片**。
- 它**不是分支**（产出值、不划臂区间）；约定 `?:` 不得与真算子重名。
