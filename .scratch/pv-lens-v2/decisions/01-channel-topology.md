# 信道拓扑：T2（横线中段信道段）对 T1（总线式）

Type: prototype
Status: resolved

## Question

用可交互原型把两种信道拓扑画出来对比，定稿 v2 的信道落地方案：

- **T2 横线式**：角色生命线按列排；一条消息 = 发送段 + 中段信道段（线型 + 名字）+ 接收段；未配对只画一半，端点是开放圆点。
- **T1 总线式**：所有角色生命线在左，竖直信道总线在右；消息从发送者水平连到总线，接收者用总线上的回指标记。

必须一并回答的**走线问题**：T2 下 `I→R` 的横线会穿过中间的 `S` 生命线，可能被读成「S 中继」。跨线弧、经信道段绕行、其它方案，哪种不误导？

素材：`ns-original`（两方）与 `ns-mutual-auth`（四方，ADR-0003 下无配对、全部挂轨）各一份。原型用假数据即可，不必接真实解析器。

判据：读者能否一眼分辨「同一条消息的两端」「消息经过哪条信道」「哪些是未配对」。

## Answer

**结论（HITL，用户判定）**：

- **拓扑定稿 = T2（横线中段信道段）**：判据「同一条消息的两端」「消息经过哪条信道」两项均判 T2 优于 T1。
- **配对 / 未配对区分认可**：配对用蓝实线、未配对用橙实线 + 空心圆，用户认为可视化不错（不改）。
- **跨中间生命线的走线 = 跨线弧**：在每一处穿过的生命线上做上拱小弧（wire-bridge 式），避免被读成「中继」；否决「直接横穿」与「沿信道绕行」。

### 后续修正（用户复看 04 原型后，2026-09 迭代）

信道 / 消息的**渲染**由 T2「横线中段信道段」改为**总线方块**（拓扑选择 T2 的语义结论不变）：

- **信道 = 总线方块**：一个**很高很扁的竖直方块**（不是线段），落在角色列之间；因为收发双方都无法确保收发内容符合预期，信道应表现为「谁都能放 / 取」的总线。
- **消息箭杆在总线两侧断开**：发送段停在总线一侧，接收段从总线另一侧起。
- **内容以方块镶嵌在箭杆中间**：发送段写**发送方实际词项**，接收段写**实际到达的词项**（配对时 = 发送方词项；接收方本地绑定名如 `m` 仍由接收方块表示）。箭头**指向目标**：发送段 → 总线，接收段 → 接收方块。
- **可配对的消息箭头用信道色**（未配对用橙色 + 空心圆）。
- **箭头在方块边缘显现**：箭杆止于接收方值方块的边缘，箭头在最后一趟绘制，**不被方块遮挡**、指向保持正确。
- 跨中间生命线的**跨线弧**不撤销（T2 的走线结论仍适用）。

该修正已在 `prototype/04-event-flag-lookup.html` 落地。
