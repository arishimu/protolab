# 生命线与信道的水平序列编排（原「通用角色左右分配算法」）

Type: grilling
Status: resolved

## Question

「人工配对」定稿要求角色按**通联图二分割**分到信道两侧（最忙的角色贴总线），同侧消息用 11px jog 错开。但原型是**手工**按 `ns-mutual-auth` 这一份样例分的（消息计数 I–R 3、I–S 2、R–S 2 → I 单独在左，R/S 在右，K 最外）。要定通用口径，让任意协议都能自动分侧：

- **主判据与优先级**：通联图二分割（割边最少）、最小化同侧消息数、最忙角色贴总线 —— 冲突时谁让谁？三者是否等价于同一个目标函数下的不同表述？
- **同侧 jog 的成立条件**：11px 下移在「同侧消息只有 R–S 两条」时成立；同侧消息变多（3 条以上、或同侧收发混杂）时，是继续逐级下移，还是改判分侧 / 改用多信道轨？
- **退化情形**：单角色（`hello` 只有内联主进程）、两角色、完全连通（任意两角色间都有消息）、两侧都最忙、奇偶角色数、K 这类「只有一条未配对步」的边缘角色。
- **确定性**：同分时的 tie-break（源码角色序？角色名字典序？），以及结果是否需要在 UI 里可见 / 可手动覆盖。
- **与间距解算的关系**：分侧只改 `x`（数组顺序仍是源码角色序 `narrativeRoleOrder`），确认不影响 ticket 08 的间隙解算与起手错位口径。

判据：换一份 3 角色样例与 `ns-mutual-auth`（4 角色）时，分侧结果都可预测、跨线弧最少、不因样例微调而翻侧。

**会话 1 续（HITL 第三轮反馈）**

用户：**「若不考虑画布编辑、仅从 `.pv` 生成视图，对一般的多生命线多信道场景，能否设计决定生命线与信道交替排列的算法，使相邻项割边数分布尽量均匀？」**

**答：能。而且它把本票从「左右二分」升级成有精确定义的问题。**

### 形式化

- **项**：生命线（角色）+ 信道（总线），全部排在同一条水平轴上，求一个**交错序列**（单信道时退化为「若干角色 | 总线 | 其余角色」）。
- **成本的关键洞察（pairing-free）**：每一条**消息步骤**（`out` 或 `in`）都连到**它自己命名的信道**，无论是否配对（ADR-0008：信道是唯一结点；ADR-0003：未配对步骤落信道轨）。所以「每个步骤到其信道的水平距离」**只依赖 AST，不依赖配对结果**：
  `Cost = Σ_steps |pos(role) − pos(channel(step))|`
  等价权重 `w(role, channel) = 该角色在该信道上的步骤数`（out + in），从 `.pv` 直接可数，**不需要 shape-only 启发式、更不需要声明配对**。这同时解决了 Q2 的输入问题。
- **等价于标准问题**：这是 **single-row facility layout（一维设施布局）/ 线性排列** 的一类特例（facility = 角色与信道，成本 = 成对绝对距离，且只连「角色–信道」二部边）。一般 NP-hard，但本例 `n = 角色数 + 信道数 ≤ ~10`，**精确解无压力**（全排列 ≤ 10!，或子集 DP `O(n·2^n)`、分支定界）。
- **「割边数 / 负载」就是这条成本曲线的斜率**：把相邻两项之间的 gap 上通过的段数记为 `load(gap)`，则 `Σ_gap load(gap) = Cost`。于是：
  - ticket 判据「**跨线弧最少**」= 最小化 `Σ load`（= 上面的 Cost）；
  - 用户要的「**分布尽量均匀**」= 压 `max load` / 压 `Σ load²`（截断/凸惩罚）。
  - 两者是**同一条负载曲线的两个读数**（总和 vs 形状），可以组成字典序目标（先压峰值、再压总和），或凸组合。

### 它顺带回答 Q1：三个候选表述是同一个目标的不同分辨率

- **单信道退化**：唯一信道 `c`，所有角色都只连它，`Cost = Σ_r w(r,c)·|pos(r) − pos(c)|`——这正是**一维加权中位数**问题，最优解 = **最忙的角色离总线最近**。⇒ 原型手工的「**最忙贴总线**」不是拍脑袋，而是这条成本的自然解（ADR-0007 点 5 背后的真实理由）。
- 「同侧消息数最少」是另加一层（依赖配对）的目标，与 `Cost` 只在「每侧 ≤2 角色」时重合；这就是 ticket 里「三者是否等价」的答案：**不等价，但都是同一负载曲线的不同采样**。
- **多信道天然可表达**「角色夹在信道 1 与信道 2 之间」——序列里两个总线之间可以夹角色，greedy 会把一个用两条信道的角色放在两条总线之间。**这恰是 ticket 14 的多信道排布问题**，两者在这一根水平轴上重叠。

### 这改变了什么（map 形状）

- 本票应**重述**为「**生命线与信道的水平序列编排**」，左/右二分降为单信道特例。
- 与 `14-multi-channel-visuals.md` 的边界需要重划：14 管**信道本身的视觉编码**（总线管、分道、配色、图例、跨线弧画法），本票管**水平次序的求解**；或两者合并。
- 若采纳，ADR-0007 点 5「通联图二分割」应改写为「一维设施布局 / 加权中位数」；11px jog 已定删除（ADR-0007 点 6 失效）。
- 与 T1/T2（用户决定）的关系：序列算法让「用户决定」从**必需**降为**可选覆盖**——seam 仍可留，但不再是默认会出错的救命稻草。

**会话 1 续（HITL 第四轮：用户给出精确形式化 + 编号修正）**

用户形式化（编号修正为 `0..n−1` 后自洽，`k ∈ [0, n−1)` 恰为 `0..n−2` 的 n−1 个缝隙）：

```
argmin_{σ ∈ S_n}  max_{k ∈ [0,n−1)}  Σ_{(u,v) ∈ E} [σ(u) ≤ k < σ(v)]
```

在无向二分图 `G = (V1 ∪ V2, E)`，`V1` = 角色、`V2` = 信道。

### 与我的形式化：同一条曲线，不同泛函 —— **不等价**

- 两者共享**同一条割边曲线** `cut(k)`（我的 `load(gap)` 就等于用户的 `cut(k)`）。
- 用户 = **min of max**（cutwidth 最小化）；我 = **min of sum**。且有一个恒等式：
  `Σ_k cut(k) = Σ_{(u,v)} w_e · |σ(u) − σ(v)|`（每条边为它跨过的每个缝隙贡献一次）——所以「min-sum」正是「**总走线长度 / 跨线弧最少**」。
- **加权下立即不等价**。暴力穷举（7! = 5040）找到的见证：`V1={r0,r1,r2}`、`V2={c0,c1,c2,c3}`（`c1` 孤立），边权（重数）：
  `r0–c0 ×1, r0–c2 ×1, r0–c3 ×2, r1–c0 ×1, r2–c2 ×2`
  - **min-max = 2**：σ = `r2, c1, c2, r1, c0, r0, c3` → 曲线 `(2,2,1,2,2,2)`，**sum = 11**；
  - **min-sum = 8**：σ = `r1, c0, r0, c3, c2, r2, c1` → 曲线 `(1,1,3,1,2,0)`，**max = 3**；
  - 穷举确认**不存在**同时取到 (max 2, sum 8) 的排列。
- 因此：**ticket 判据「跨线弧最少」= min-sum，而用户现在给的是 min-max，两者在加权图上冲突**——这是必须拍板的分叉，不是表述差异。
- **无权**情形：本会话对无权图做了穷举（一般图 n ≤ 6 全图；二分图 n ≤ 6 全图）与随机（一般图 n=7 三千图；二分图 n=7/8/9 近万图），**未找到**两种最优不相交的实例（无权小图上似乎总存在共同最优）。但这与我们的实例无关：**我们的 E 天然带重数**（同一角色对同一信道的多个 `out`/`in` 步骤是多个走线段），加权见证已给出。此无权观察未证，仅作记录、不作依据。

### 复杂度

cutwidth 与 MLA 一般图都 NP-hard；但本例 `n = 角色数 + 信道数 ≤ ~10`，**两种泛函都可精确解**（全排列 ≤ 10!，或子集 DP `O(n·2^n)`、分支定界）。规模不是约束，泛函选择才是。

### 附带：「均匀」未必等于 min-max

min-max 只压**峰值**，不保证曲线平；若「尽量均匀」是字面义，可选凸成本 `Σ_k cut(k)²`（或对排序后曲线做字典序 / majorization）。min-max 是最小化峰值的标准替身。

### 重排后的待决（取代上一轮 T5–T8 中受影响项）

❓ **T6′ — 目标泛函**：(i) min-sum（= 跨线弧最少，票判据）；(ii) min-max（用户形式化）；(iii) 字典序「先 min-max、再 min-sum」；(iv) 凸成本 `Σ cut²`（字面「均匀」）。

➡️ 建议 **(iii)**：既是用户形式化的严格细化，又满足票判据；只有当「均匀」是字面义、需要压曲线形状时才上 (iv)。

❓ **T7′ — E 的定义**：简单邻接（角色用过该信道 = 1 条边，无权）还是**步骤多重边**（每个 `out`/`in` 一条，权重 = 次数）？

➡️ 建议：**步骤多重边**——它才是物理走线段数，且与 ADR-0008「信道是每个步骤的结点」一致；代价是承认 T6′ 的选择真的会改变结果。

❓ **T5 / T8 不变**：是否把本票重述为「生命线与信道的水平序列编排」（单信道为特例）、以及与 ticket 14 的切分。

## Answer

**HITL 定稿（用户逐轮确认，末轮「同意」）**：本票由「角色左右二分」**重述为「生命线与信道的水平序列编排」**，用**加权 min-max 割边**目标求解，输入是 **pairing-free 的角色–信道多重边图**。

### 1. 模型：水平序列（取代左右二分）

- 规范叙事视图的水平轴是一个**交错序列** `σ`，项 = 生命线（角色）∪ 信道（总线）。
- **左/右二分降为单信道特例**：只有一个信道时，序列退化为「若干角色 │ 总线 │ 其余角色」。
- 多信道天然表达「角色夹在两条总线之间」——用两条信道的角色被摆到两条总线之间。

### 2. 输入图 `G = (V1 ∪ V2, E)`（pairing-free）

- `V1` = 角色（`narrativeRoleOrder`），`V2` = `.pv` 里出现的信道。
- `E` = **每个消息步骤（`out` / `in`）一条边**，连「角色 ↔ 该步骤点名的信道」；**重边**（同一角色对同一信道的多个步骤 = 多条边；权 `w_e` = 次数）。
- 边集只依赖 AST，**不依赖自动 / 人工配对结果**（ADR-0003：未配对步骤落信道轨；ADR-0008：信道是每个步骤的结点）⇒ 水平序列在用户配对前后**稳定不变**。

### 3. 目标：min-max 加权割边（用户形式化）

```
σ* = argmin_{σ ∈ S_n}  max_{k ∈ {0..n-2}}  cut(k)
cut(k) = Σ_{(u,v) ∈ E} w_e · [σ(u) ≤ k < σ(v)]
```

- **拒绝 min-sum（MLA）**：本会话已证两者不等价，见证 `V1={r0,r1,r2}`、`V2={c0,c1,c2,c3}`（`c1` 孤立），边权 `r0–c0 ×1, r0–c2 ×1, r0–c3 ×2, r1–c0 ×1, r2–c2 ×2`：min-max = 2 ⇒ sum ≥ 11；min-sum = 8 ⇒ max = 3。
- ticket 正文原措辞「割边最少」（min-cut）是笔误，已由上式取代。
- 规模 `n = |V1| + |V2| ≤ ~10`，全排列或子集 DP `O(n·2^n)` 精确解；一般 NP-hard 不构成障碍。

### 4. 确定性（三级 tie-break）

1. **min-max**（上式）。
2. 同分中取**降序 cut 曲线字典序最小**（majorization-minimal = 最均匀）——「分布尽量均匀」的严格化，**不退化成 min-sum**。
3. 仍同分按**源码序**（角色 `narrativeRoleOrder`、信道按源码首次出现序）取字典序最小的 `σ`。

### 5. 退化情形：不做特例

- 0 项不画；1 项 / 无缝隙 `max ∅ = 0`；`E = ∅` 任一排列都最优 → 落规则 3；无步骤的孤立角色由规则 3 定位置、不影响目标。
- **`processK` 不是孤立点**：它有 `in(c, …)` ⇒ 边 `K–c`（权重 1），自动被摆到总线附近；旧「边缘角色」特例消失。

### 6. 同侧 jog：删除

- `SAME_SIDE_JOG = 11px` 的存在理由是「同侧收发段共线重叠」；ADR-0008 已定「各端 y 必须不同」，共线不再发生。

- 多信道下的走线变体归 ticket 14。

### 7. 接口
