# 03: 结构化条件与分支作用域

**What to build:** 让读者直接看出 `if` 与 `get` 的守卫、`then`/`else` 范围及分支内的值引用，并能区分控制流分支与产出单个值的条件表达式。

**Blocked by:** 01: 叙事 IR 兼容层与基线生命线; 02: 值绑定与词项追踪.

**Status:** ready-for-agent

- [ ] `if` 与 `get` 在角色有序 `items` 中形成连续的 `branch`、可选 `else`、`join` 标记流；`join` 恒存在，分支范围由标记流恢复。
- [ ] item 守卫与 `PvTerm.conditional` 共用结构化 `Condition`：比较 `=`/`<>`、`&&`/`||` 复合子句和无法结构化时的 `unknown` 原文。
- [ ] 同名绑定按分支臂帧栈解析，`else` 引用不会误指向 `then` 的绑定；嵌套与离开分支后的引用也正确。
- [ ] 守卫在分叉前显示等值检查盒；复合条件逐子句成行，内嵌解构有自己的方法盒和派生芯片，空 `else` 显示 `else ∅`。
- [ ] `then` 恒占偏移臂道；嵌套主要臂道最多两条，更深层以缩进和角标表达；分支默认展开，并提供显式折叠开关。
- [ ] `let x = if c then a else b` 显示带 `?:` 的选择盒和条件芯片，不产生分支臂道。
- [ ] 测试覆盖连续标记、复合/未知条件、臂内同名绑定、单臂/空臂/嵌套分支及选择盒。
