- **已锁定原则**（本 effort 的 grilling 结论，见 `docs/adr/0004`）：
  1. **视图语义模型 = 消息序梯子**：纵轴 = 消息序；一条**消息**是一个对象，发送端与接收端共享同一 y。角色是竖直生命线；信道是一等视觉元素。
  2. **信道 = 总线方块（很高很扁的竖直方块）**，落在角色列之间：一条消息 = 发送段 + 总线 + 接收段，内容装在**方块里、镶在箭杆中间**；发送段写发送方实际词项，接收段写**实际到达的词项**；箭头**指向目标**（发送段→总线，接收段→接收方块），可配对箭头用**消息身份色**（ADR-0008、ADR-0010）、未配对橙色。跨中间生命线的走线用**跨线弧**；T2/T1 的对比与拓扑定稿见 ticket 01。
  3. **两层信息模型**：**消息层**（共享、跨角色，承载发送方实际放上信道的 wire term）+ **值层**（每角色本地的记号节点与派生边）。接收步骤是两层的连接点。
  4. **本地步骤不住箭头**：`new` / `let` / `if` / `get` / `insert` 是生命线上两消息之间的**本地节点**；`event` 是**专门标记**（旗/菱形），供对应性查询引用。
  5. **单符号会话**：一条生命线 = 该角色的一个符号实例；`!` 只表示「可重复」。
  6. **未配对挂轨 + 多方不自动配对**：沿用 ADR-0003；多方协议不画角色间连线。多方**自动**配对仍关闭，但未配对步骤可由用户**人工配对**（见 Decisions 的 05、09 与 ADR-0005 / ADR-0007）；多方纵轴为**局部梯子**（各角色本地序，不共享行）。
  7. **event 交互**：点击两支旗 → 查表；实现为预跑**全部有序对** `inj-event(eᵢ) ==> inj-event(eⱼ)`（同参数共享），缓存后点击查表。
  8. **跨角色同实体不自动连**：值层保留各角色自己的记号；不做跨角色等价推断（攻击场景下会推错）。
  9. **人工配对的一对多 = 一次广播扇出**（见 `docs/adr/0007`）：按**发送端**归组，一个 `out` + 它的全部 `in` = **一行**（一条发送段进信道 + N 条接收段出信道，同 y，标 `广播 ×N`）；**接收端**被多条消息收到时在多行各出现一次，用「收到 ×N」竖梁连起。交互 = 画布点选、重复点源做一对多；无拖拽、无局部序控件。
  10. **广播 · 跨序是合法态**：广播行位置与角色本地序冲突时自动拆环并标 `广播 · 跨序`，不算冲突；**放宽**了 ticket 05「同一消息同 y」与 ADR-0006「同 y 硬约束」。角色相对信道按**通联图二分割**（I 左 / R·S 右），收发同侧时接收段在总线边竖向下移 11px 错开。
- 画对优先于画全（ADR-0003 精神）；**编排**（走线、折叠）先 prototype 再定稿。

- [密度与折叠](decisions/04-density-folding.md)：**定稿 A 为骨架（分段折叠）+ B 的 hover 浮卡 + 幽灵值块**；C 的角色整体折叠不做。**折叠 = 默认显示状态，不是压缩手段**（与 ticket 08 分开：默认密度归本票，空间不足时的压缩次序归 08）；**折叠粒度 = 整个算子簇折成一格**；折叠块表面直接写内含算子名（`▸ adec +2`），其**下方**留下游还要用的**虚线幽灵值块**（需 ticket 07 的引用数据）；**角色折叠只隐细节、不动行距**。原型 `prototype/05-density-folding.html`。

- [core 模型扩展的最小形状](decisions/07-core-value-model.md)：**端模型 + 派生 IR**——`ParseResult` 只出「消息端」+ 每角色有序 `items`（`message` / `new` / `let` / `guard-if` / `get` / `insert` / `event`），两端的**消息**由 core 纯函数把自动配对与人工意图边合成（统一 `MessagePairing { outEnd, inEnd, origin }`），未配对端是 `MessageRow` 的独立分支而非 `in: null`；顶层 `bindings` 表（角色参数 / `new` / `in` / `let` / `get` 各一条，稳定 id，不预计算反向引用），`variable` 叶子标 `bindingId`，**`new` 名并入变量作用域**；`PvTerm` 增 `conditional` 节点；`let` 右端词项与 `event` 参数首次结构化；`StepAnnotations` 与 `before` / `after` 挂载制删除（item 的真实位置即其位置）。
- [自适应纵向间距模型：计算单元 / 等间距 / 最小值](decisions/08-adaptive-spacing.md)：**定稿「单一弹性间距 + 等距初值 + 硬约束局部插值 + 内容决定高度」**——放弃视口预算，改由**单一连续紧凑度参数**驱动唯一弹性值 `gap.unit ∈ [18,26]`；`gap.row / gap.group` 由倍率派生 + 绝对下限，压缩次序 `group → row → tight` 靠**下限高低**先后触底；计算单元为闭集（参数簇 / 值方块 / 算子簇 / 事件 / 本地步骤 / 折叠条 / 消息行），**参数簇与算子簇刚性、内部永不变**；间隙内单元顶紧、消息行在间隙底部、矮栈角色余量贴行上方；复用时的**跨角色耦合是硬等式**（发送方单元边界 = 「消息行 + 接收方簇底」）；硬约束赢过等距，顶死则**显式标冲突 + 长高**。多方 = 各角色独立竖直栈，取 max 高度；人工配对 = 同 y 硬约束（接口）。见 `docs/adr/0006`；紧凑度控件是否露出归 UI。
- [人工配对：点选声明 / 广播扇出 / 接收端多行梁](decisions/09-manual-pairing.md)：**定稿「画布点选 + 一对多 = 一次广播扇出」**——点源再点目标即声明，**重复点源**做一对多（无上限）；一行 = 一次广播（一个 `out` + 全部 `in`，一条发送段 + N 条接收段，标 `广播 ×N`）；接收端被多条消息收到时多行出现 + 「收到 ×N」竖梁；**广播 · 跨序为合法态**（自动拆环 + 琥珀标记，非冲突）；**角色按通联图二分割**（I 左 / R·S 右，最忙贴总线），收发同侧时接收段在总线边下移 11px 错开。原型 `prototype/06-manual-pairing.html`；新增 `docs/adr/0007`，取代 ADR-0005 的「一对一禁止」。
- [广播行的值层 / 事件对齐与「收到 ×N」梁堆叠](decisions/10-broadcast-row-alignment.md)：**定稿「信道 = 扇出 / 合流的唯一结点 + 一色一消息 + 同色柱 + 整团刚性」**——一发多收 = 一条进信道、出来一分为多；多发一收 = 多条进信道、出来多合为一；**各端 y 必须不同**（取消共享行 y，因此「广播 · 跨序」与「收到 ×N 梁」一并删除）；颜色 = 消息身份，信道管加宽为多道、每条消息一根同色柱连其各端；扇出 / 合流整团 = 一个刚性间距单元。原型 `prototype/07-broadcast-row-alignment.html`；新增 `docs/adr/0008`（部分取代 ADR-0007 的点 2/3/4，修订 ADR-0006 的「同 y 硬约束」与跨角色耦合）。遗留：消息色 / 值色 / 信道色语义冲突归 ticket 14。
- [`if` 分支作用域与构造算子进 item 序列（模型）](decisions/12-branch-scope-model.md)：**定稿「显式分支标记流」**——`guard-if` 不再独立，`RoleItem` 增 `BranchMarker`（`branch` 载守卫 / `else` / `join`），`join` 恒发、`branch…join` 间为连续臂区间（供 13 取臂、08 视需要当刚性单元）；**臂范围不存**（下游扫栈）。条件结构化且 item 级 `if` 与 `PvTerm.conditional` **共用 `Condition`**（`=` / `<>` 比较子 + `&&` / `||` 子句 + `unknown` 兜底；替掉 07 的 `conditionText`）。**构造 / 解构走声明表**：`ParseResult.destructors` 收 `reduc` 表头名，`ApplicationTerm` 不标注；元组按结构性构造。**修正 07 来源规则 6**：引用解析改 **arm 帧栈**（`branch` 入帧 / `else` 换帧 / `join` 弹帧，自内向外取最近同名绑定），`Binding` 不加 branchId。**部分修订 07 的「`guard-if` 是本地步骤」**；解除 [13](decisions/13-conditional-rendering.md) 的阻塞。
- [`if` 守卫与纯构造方法的呈现（画法）](decisions/13-conditional-rendering.md)：**定稿「等值检查盒 + 并行臂道 + 方向区分构造」**——守卫 = 竖栈里的倒置梯形**等值检查盒**（无输出，两操作数同色方块贴上；内嵌解构输出派生虚线芯片喂入；复合条件逐子句成行、连接词作字形、不加括号），落在主生命线上、分叉前；`then`/`else` = **并行臂道**（then 恒偏移一条道、道号 = 1 + 外层 else 数、**封顶 2 道**、更深改道内缩进 + 角标），`branch…join` = 08 的**刚性单元**且**默认不折叠**，空臂画 `else ∅` 桩；构造与解构**同梯形、只靠方向区分**（解构竖向 / 构造横置朝消息）；只有绑定拿值方块，未绑定内联构造是**虚线 wire 词项芯片**；条件表达式 `let x = if…then…else` = 梯形**选择盒**（盒内 `?:`、条件作外侧芯片），不算分支。原型 `prototype/08-conditional-constructors.html`（默认变体 D）。补齐 12 留的「`branch…join` 是否 08 刚性单元」（是）；新增词表「等值检查盒 / 选择盒 / 分支臂道 / wire 词项芯片」。

- [生命线与信道的水平序列编排（原「通用角色左右分配算法」）](decisions/11-role-channel-sequence.md)：**定稿「加权 min-max 割边序列」**——水平轴 = 生命线与信道的**交错序列**（左/右二分降为单信道特例）；输入 = **pairing-free 的角色–信道多重边图**（每个消息步骤一条边、重边计次，不依赖自动/人工配对）；目标 = `argmin_σ max_k cut(k)`（用户形式化；**min-sum / MLA 被证不等价并否决**，加权见证见票）；三级 tie-break（min-max → **降序 cut 曲线字典序最小** → 源码序）；退化情形不做特例（`processK` 有 `K–c` 边、非孤立）；**删除同侧 jog**（ADR-0007 点 6 失效），「**任两消息端 y 不同**」改立为 ticket 08 解算器硬约束、删 ticket 09 的 `BASE_IDX`；MVP 无 UI 覆盖，只留「外部顺序约束」seam。新增 `docs/adr/0009`；原型另开 [子票 15](decisions/15-role-side-sequence-prototype.md)。
- [多信道视觉](decisions/14-multi-channel-visuals.md)：**定稿「信道不占颜色」**——信道身份 = 水平序列位置 + 序号字形（① ② ③）+ 总线方块边框线型；多信道 = **并列多条中性总线方块**（否决「同一总线分道」）；颜色只留给**消息身份色**（消息柱 / 段 / 箭头）与**值身份色**（值方块）；跨线弧保留、未配对橙点保留、同信道硬约束不变。原型 `prototype/10-multi-channel-visuals.html`（变体 A 定稿）；fixture `pv-lens/packages/core/fixtures/pv/multi-channel.pv`；新增 `docs/adr/0010`，收口 ADR-0008 遗留。
