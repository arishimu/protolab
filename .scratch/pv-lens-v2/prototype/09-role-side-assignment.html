原型 09 · 生命线与信道的水平序列编排

问题：把 ADR-0009 的算法做成可看的原型，验证它在真实与合成样例上 「可预测、确定、cut 曲线符合 min-max 且同级最均匀」。
水平轴是生命线（角色）∪ 信道（总线）的一个交错序列 σ；目标 σ* = argminσ maxk cut(k)， cut(k) = Σ(u,v)∈E we·[σ(u) ≤ k < σ(v)]， E = 每个消息步骤一条边（重边计次）。原型 · 一次性 · 验证用

6口径与来源

真实 fixture 的图怎么来的

用 pv-lens/packages/core 的 parsePv + narrativeRoleOrder 实跑导出：每个消息步骤（out / in）一条边，连「角色 ↔ 该步骤点名的信道」；同一角色对同一信道的多个步骤合并为一条边、w = 步数（重边计次）。角色顺序 = narrativeRoleOrder；信道顺序 = free 声明序。已核实：
hello → main:1|c　handshake-fixed → clientA:3|c, serverB:3|c　ns-original → processA:6|c, processB:5|c　ns-mutual-auth → I:6|c, R:7|c, S:2|c, K:1|c

求解

本页用全排列暴力枚举（样例 n ≤ 7，最多 5040 个排列），逐条算 cut 曲线，再按三级 tie-break 选。真实实现按 ADR-0009 用 O(n·2^n) 子集 DP，规模 n ≤ ~10；本原型不验证 DP 的实现，只验证目标函数与三级 tie-break 给出的答案。规则 3 的比较用「项在源码中的下标」，与枚举顺序无关 —— 所以「打乱枚举顺序」不影响结果（见第 2 节的按钮）。
