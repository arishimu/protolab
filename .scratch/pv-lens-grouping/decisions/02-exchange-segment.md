# 决策票 02：交换段

Type: prototype
Status: resolved
Blocked by: —
Resolved: 2026-11-05

## Question

消息层的交换段如何定义成员与边界？因果凸怎样计算？跨段边如何保留？哪些范围必须拒绝？V1 的限制是什么？本票为阶段 3 提供唯一口径。

## Answer

以下决策按 `PLAN.md` 阶段 0 口径起草，作为阶段 3 的实现依据。

### 1. 因果 DAG 与因果凸

1. **顶点 = 完整消息**（不是消息端）。边的来源：
   - 配对边：同一 `MessagePairing` 的发送端 → 接收端，表达消息因果；
   - 本地序边：同一角色相邻消息步之间，按源码顺序连接。
2. **因果凸**：候选消息集合 `M` 合法，当且仅当对任意 `A, C ∈ M`，若存在有向路径 `A → … → B → … → C` 且 `B` 是消息，则 `B ∈ M`。等价说法：`M` 等于它在因果 DAG 上的凸闭包。
3. 存在顺序冲突（因果环）时，先在 SCC 收缩图上计算凸性；一个 SCC 必须整体在段内或整体在段外，不得拆分。冲突数计入 `hiddenCounts.conflicts`。
4. 消息列表按因果 DAG 的确定性拓扑序排列；tie-break 依次使用消息编号与源码偏移。候选枚举顺序打乱后，水平序列与列表顺序不变。
5. 用户选择起止消息得到候选区间后，工具计算凸闭包：
   - 闭包等于候选：允许创建；
   - 闭包大于候选：就地提示「因果凸闭包需要加入 N 条消息」，列出缺失消息，并提供「扩展到凸闭包」；不得静默扩大或创建半条段带。

### 2. 整条消息规则

1. 交换段只保存 `messageIds`，不保存消息端。
2. 一条消息的**全部端点**必须同属一段；任一端点在段外时该范围非法（I9）。
3. 消息列表只允许按消息勾选，不提供按端点勾选；「切半条消息」通过非法范围演示项验证拒绝路径。
4. 广播扇出与合流：一条消息的全部接收端 / 发送端属于同一条消息，因此必须整体包含或整体排除；不把扇出或合流拆到两个段。

### 3. 边界与跨段边

1. 段框由段头、段带与边界标记组成：段头位于段带上缘，承载参与角色、消息编号区间、消息条数与隐藏项计数；段带覆盖段内消息涉及的角色生命线；边界标记标明段起止。
2. 段只覆盖参与角色与信道；不遮挡无关生命线。
3. **跨段边**：一端在段内、另一端在段外的消息因果边。跨段边必须完整可见，不得穿过段头、段带或计数标签；在折叠态沿段框外侧的 gutter 绕行，在展开态按原因果位置绘制。
4. 若跨段边无法清晰保留，该消息集合不得声明为交换段；工具在创建前检测并拒绝。
5. 段外消息保持原有因果位置与 y 关系；展开态与改动前基线一致。

### 4. 非法范围

以下情形必须就地拒绝，给出可读中文原因，不产生半条段带：

| 情形 | 判定 | 提示要点 |
|---|---|---|
| 切断消息 | 任一消息端点在段外 | 说明该消息的发送/接收端必须同属一段 |
| 非因果凸 | 候选 ≠ 凸闭包 | 列出缺失消息，提供扩展操作 |
| 跨信道 | 段内消息涉及一个以上信道 | 说明 V1 仅允许单信道段 |
| 多方 | 段内涉及两个以上角色 | 说明 V1 仅允许两方协议 |
| 广播/合流拆分 | 同一消息的端点未整体包含 | 说明必须整体包含或整体排除 |
| 嵌套段 | 与已有段重叠 | 说明 V1 不支持段中段 |
| 拆分冲突 SCC | 冲突环跨段边界 | 说明冲突必须整体包含或整体排除 |
| 非连续选择 | 拓扑序上不连续 | 说明交换段是一段连续消息集合 |

### 5. V1 限制

- 仅两方协议可创建；多方协议入口禁用并说明原因，多方段留待后续版本。
- 仅单层，不支持段中段。
- 仅允许单信道段；跨信道范围按非法处理。
- 自动建议不进入 V1；只提供手动范围选择。
- 仅折叠消息行；段内事件不隐藏，以段头事件芯片保留，展开后回落到原位。事件芯片不计入隐藏计数。
- 段内本地步骤与分支若被折叠，计入 `hiddenCounts.branches`；未配对端点计入 `unpaired`；布局冲突计入 `conflicts`。

### 6. 计数与状态

1. `hiddenCounts` 由段成员集合与配对结果计算，不由 UI 估算：
   - `messages`：段内完整消息数；
   - `unpaired`：段内没有配对的消息端点数；
   - `branches`：段内被折叠的本地步骤与分支数；
   - `conflicts`：段内布局冲突或顺序冲突数。
2. 段内未配对步骤展开后落在信道轨，橙色标记可见。
3. 段状态（成员、名称、折叠状态）仅存会话内存，切换协议或刷新即清除；支持重命名与移除，移除后无残留段带。
4. 水平序列、角色顺序与消息因果序不因建段改变。

### 7. 与操作组的交互

1. 交换段折叠只影响消息层；值层密码操作组的展开状态独立保留。
2. 段内消息展开时，消息行、消息柱与端点位置与改动前基线一致。
3. 密度折叠与语义折叠记法不同：段框用双线边框与边界标记，密度折叠用虚线。

## 原型交互语义（2026-11-05 复核补充）

原型中每个控件的行为口径如下；阶段 3 实现时按此对齐，不得只做视觉。

1. **勾选消息**：只选整条消息，不提供端点选择；选择是临时状态，不写 `.pv`。
2. **快捷选择**：只预设勾选，不自动创建；校验随选择即时更新。`M1–M4` 与 `M1–M5` 会分别同时触发跨信道与第三方两条原因，这是样本路由结构本身导致，不是重复计数。
3. **校验清单**：连续区间、整条消息、因果凸、两方以内、单信道、不与已有段重叠，逐项显示通过 / 不通过与原因。
4. **切半模拟**：勾选后 `M2` 在消息列表与画布标记「仅发送端」，并按切断消息拒绝；不改变消息数据与源码。
5. **创建**：校验通过后按所选区间创建并展开，随后清空选择；已有段时拒绝创建，需先移除。原型一次只保留一个段；V1 正式实现允许多个互不重叠段。
6. **折叠 / 展开**：工具栏按钮、段头单击、段卡片按钮三处同步；折叠只隐藏段体，段头计数、事件芯片与跨段边保留。
7. **模拟顺序冲突**：只把段内 `conflicts` 设为 1 并显示冲突注记；不改变消息、因果序或校验结论，切换协议后清除。
8. **模拟切换协议**：清空段、选择、冲突与切半状态；演示会话内存边界，不切换真实文件。
9. **段名**：会话标签，编辑即时更新段头；留空显示「未命名段」；名称不是安全结论。
10. **灰度 / 打印**：只改变渲染预览，不改变选择或段状态。
