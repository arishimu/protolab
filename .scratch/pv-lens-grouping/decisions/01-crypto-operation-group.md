# 决策票 01：密码操作组

Type: prototype
Status: resolved
Blocked by: —
Resolved: 2026-11-05

## Question

值层的密码操作按什么粒度成组？如何嵌套？展开状态归谁？分类来源与置信度如何可见、如何被用户覆盖？本票为阶段 1–2 提供唯一口径；未决前不得写生产代码。

## Answer

以下决策按 `PLAN.md` 阶段 0 口径起草，作为阶段 1–2 的实现依据。

### 1. 分组粒度

1. **一次密码操作出现 = 一个密码操作组**。组成员是该操作自身的方法盒、其输入值方块与输出值方块；输入若本身是另一次密码操作，则成为**子组**，不并入父组（见第 2 条）。
2. 参数簇、未绑定的线上词项芯片、元组、裸变量引用、等值检查盒、选择盒、事件标记、本地步骤**不单独成组**。
3. 一次操作只属于一个组；同一词项中并列的两个操作各自成组，不合并为「密码算法块」。
4. 组不跨角色合并；不推断不同角色的同名绑定为同一值。

### 2. 嵌套规则

1. 按词项结构嵌套：`aenc(sign(m,sk),pk)` 中 `aenc` 是父组，`sign` 是子组。父组的 `members` 不含子组成员；`parentId` 指向父组，子组 `parentId` 为父组 id。
2. 外层折叠显示**内层组数量**；内层成员计入外层 `hiddenCount`（隐藏计数与展开后的可见成员总数一致）。
3. 同一层不合并不同操作；嵌套深度不设人为上限，但布局只按实际深度增加缩进。
4. 组 id 由角色名、操作种类、首个方法盒的稳定 id 与源码偏移生成；同一输入得到同一 id。成员只保存方法盒与值方块 id，不保存坐标。

### 3. 展开状态

1. 默认状态由**细节层级**决定：概念层折叠全部操作组；结构层展开操作组；语法层全部展开。交换段与操作组各自独立记忆，不互相强制。
2. 展开状态是会话内存，不持久化；切换协议或刷新即回到该层级默认值。
3. 折叠态高度低于展开态；折叠不得改变水平序列、角色顺序与消息 y 的相对关系。
4. 键盘 Enter / Space 等价于单击；组头可聚焦并有可见焦点环；折叠/展开有 `aria-expanded`。

### 4. 分类来源与置信度

| 操作种类 | 识别依据 | 来源 | 置信度 | 自动折叠 |
|---|---|---|---|---|
| 对称加密 / 对称解密 | 方程形如 `d(c(m,k),k) = m`，构造子与析构子共享密钥参数 | 方程匹配 | 高 | 是 |
| 非对称加密 / 非对称解密 | 方程形如 `d(c(m,pk(sk)),sk) = m` | 方程匹配 | 高 | 是 |
| 签名 | `checksign(sign(m,sk),pk(sk)) = m` 或 `getmess(sign(m,sk)) = m` | 方程匹配 | 高 | 是 |
| 哈希 | 无析构子的单参数函数，名称或类型命中哈希别名 | 名称启发 | 中 | 是，标注「名称启发」 |
| 密钥派生 | `pk(sk)` 形式的单向函数，结果用作密钥 | 名称启发 | 中 | 是，标注「名称启发」 |
| 未识别 | 无方程匹配且无别名命中 | 未识别 | 低 | **否**，保留原始函数名 |

1. 方程匹配必须优先于名称启发；两者都命中时取方程匹配。
2. 构造 / 解构方向由使用位置决定：写在构造词项里为 `construct`，作为 `let` / `in` / `get` / 条件中的析构函数调用为 `destruct`。
3. 关键参数与密钥身份只保存 `TermReference`（指向 `PvTerm` 与 span），不复制词项文本；折叠态显示操作种类、方向、关键参数、密钥身份与隐藏计数。
4. 「未识别」不产生组、不自动折叠，提示为中性说明；不得把低置信标签写成协议事实。

### 5. 用户覆盖

1. 审计面板按组列出：角色、种类、方向、来源、置信度、隐藏计数、底层 `fun`/`reduc` 名称、源码 span。
2. 用户可把某组种类改为任意 `OperationKind`；来源变为「用户声明」，置信度显示为「用户声明」而非自动值；标签与注解同步更新。
3. 覆盖键为稳定组 id（角色 + 首个成员 + span）；仅存会话内存，切换协议或刷新即清除，不回写 `.pv`。
4. 提供「重置」恢复自动分类结果；重置只影响该组。
5. 用户覆盖不改变 `.pv`、查询集合、验证结论与消息因果序。

### 6. 隐藏计数与幽灵值块

1. `hiddenCount = 折叠态被隐藏的成员总数（含子组成员）`，由成员集合计算，不由 UI 估算。
2. 被组外后续步骤引用的输出值，在折叠组下方保留**同色幽灵值块**，颜色与序号和折叠前一致（I6）；无组外引用则不保留。
3. 幽灵值块不计入 `hiddenCount`，因为它仍可见。
4. 折叠态摘要至少显示：操作种类、方向、关键参数、密钥身份、隐藏计数；内层组数量另行显示。

### 7. 失败与降级

1. `reduc` 方程解析失败时降级为诊断，不抛异常；分类回退到名称启发或未识别。
2. 未知函数、降级语句与语法错误均按原文保留，不被分组隐藏。
3. 分组 IR 是纯函数输出，不依赖 DOM、不调用宿主 API。

## 原型交互语义（2026-11-05 复核补充）

原型中每个控件的行为口径如下；阶段 2 实现时按此对齐，不得只做视觉。

1. **细节层级**
   - 概念层：所有操作组折叠，密度折叠保持折叠；折叠态用幽灵值块承接组外引用。
   - 结构层：所有操作组展开（含嵌套子组），密度折叠保持折叠；展开态显示真实值块，不再显示幽灵块。
   - 语法层：操作组与密度折叠全部展开；最终结构与基线逐节点一致。
   - 三档只重置展开状态，不改变种类、来源、置信度或用户声明；用户声明跨层级保留。
2. **逐组开关**：单击组头只切换该组；父组展开不强制子组展开，嵌套组各自记忆状态。
3. **隐藏项**：组内操作盒与值块总数，含嵌套组；与展开后可见成员数一致；不是消息条数。
4. **审计下拉**：修改即记为用户声明，仅存会话内存；选择值等于自动种类即撤销声明；重置在无声明时禁用；不改 `.pv`。
5. **定位**：只高亮组与源码行，不改变折叠状态。
6. **全部展开 / 全部折叠**：作用于所有操作组与密度折叠，清空逐组状态但保留用户声明。
7. **灰度 / 打印**：只改变渲染预览，不改变分组数据、展开状态或用户声明。
8. **未识别操作**：不建组，因此没有可折叠对象；保留原名、标记低置信，不计入任何组的隐藏项，也不标记为错误。
